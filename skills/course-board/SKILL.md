# 课程看板（只读展示）

一眼看清「现在在学什么」。只读展示：不解锁、不编辑、不生成看板、不写日志、不碰 `raw/`。

## 读取

1. 读 `../wiki-save/SKILL.md` 的「入口与配置」部分，定位 Wiki 路径并读取原有规则；不进入资料摄取或制卡流程。
2. 读 `wiki/courses.md`（Obsidian 看板）、`wiki/courses.html`（浏览器看板）与 `wiki/courses/*.md`（状态源）。两个看板都是生成物，同一份状态的两种渲染：与状态源不一致时以状态源为准，并说明需要重新生成。
3. 用 `../course/course-state.mjs verify <courses 目录> <看板文件>` 核对只读锁、状态文件标记、必备段落和看板一致性。它只读取和报告，不改文件。

## 输出

在回复里直接给出（不写文件）：

- 一行「现在在学」：课程名 + 当前周。
- 每门课一小块：本周活动（`x/y`，逐条标 `[x]`/`[ ]` 与任务名）、总目标进度（`x/y`）、上次记录日期、下次起点。
- 结尾注明：数字是「已核实的计划项」，不是掌握率；状态源文件路径；看板页路径（可在 Obsidian 打开 `wiki/courses.md` 看同一份内容）。
- 用户想看网页版时给出绝对路径并提示打开方式：`open "<Wiki 绝对路径>/wiki/courses.html"`（`file://` 直接打开即可，无需服务器、不联网）。页面里没有输入框、按钮或任何编辑入口；不要描述成「可以改的地方」。

课程多时先给一张汇总表，再只展开用户问到的那门课。

## 只读约束

- 不写入任何文件，包括看板、日志、索引和图片。用户要图片时说明这由 `course` 生成；用户可在 Obsidian 直接看 `wiki/courses.md`，在浏览器看 `wiki/courses.html`。
- 网页看板或 Markdown 看板过期时，只报告「需要重新生成」，给出 `course` 里的两条命令（`dashboard` + `render-board.mjs`）并询问是否现在做；不自己生成，也不静默重建。
- 用户要打勾、撤销勾（抵消）、收课、改计划或绑定资料时，说明属于 `course` 的写入流程并询问是否现在做；不要自己解锁文件去改。
- `verify` 报出目录可写、缺少状态标记、看板过期等问题时，如实报告并给出修复步骤（`course` 技能里的解锁 → 编辑 → 上锁 → 刷新看板），不静默重建看板。
- 用户问「状态有没有被人改过」时，只报告权限与一致性校验结果；校验能发现不一致，不能证明是谁改的，也不要声称内容绝对未被改动。
- 后续界面照这个只读契约实现：只展示，不提供人工修改入口。
