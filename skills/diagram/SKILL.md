# 用字符画图

讲解时多用图。一块图只讲一个概念，比一段文字更快被看懂。画之前先确认有据可画：只画用户提供或你实际读到的内容。

**职责边界**：本技能只负责「把已知事实画成字符图」。知识的讲解与检验交给 `teach` 的流程；需要渲染成图形界面（复杂流程图、有交叉连线的图）改用 ` ```mermaid `，由宿主渲染，不在本技能范围内。

## 何时画、画哪种

| 想表达 | 用哪种图 | 说明 |
|---|---|---|
| 步骤、流程、因果 | 流程/方框图 | `[输入] ─▶ [处理] ─▶ [输出]`；分支用 `┌ ┬ ┐` / `└ ┴ ┘` |
| 数量、排名、对比 | 条形图（方块） | `████░░░░`；同列对齐，标出刻度或单位 |
| 趋势、随时间变化 | 迷你折线 | 高点用盲文 `⣿⣷⣶⣤` 或方块 `▁▂▃▅▇`；保留端点与极值 |
| 状态、覆盖、矩阵 | 状态板/矩阵 | 分级用 `○ ● ◆` 或方块深浅，表头写明列义 |
| 层级、分类、分支 | 树 | `├─` `└─` 缩进；同一层缩进相同 |

选图规则：一块图一个概念；两个小图胜过一个大图。**节点超过 6 个、或连线会交叉时，不要硬画字符图，改用 ` ```mermaid `。**

## 教学规则（改写自 show-dont-tell）

- **只画已核实的事实。** 字符图看起来像权威数据，把猜测画进框里比含糊的文字更糟。数值只用用户提供或你实际读取到的，**不编造**；缺失或估算的值要显式标注（如 `?`、`≈`）。
- **一块图一个概念。** 需要图例说明的图就太密了，拆开。
- **图下一行说明「这张图说明什么」。** 正文只承载图说不出的东西：结论与下一步，最多一两句。图内用名词短语做标签，句子留在图外。
- **把答案或重点标出来。** 当某一行/某个分支正是用户问的，直接指出来：`◆`、`◀── 重点`，不要让人自己找。一张处处高亮的图等于没有高亮。

## 输出格式

- 字符图放在 ` ```text ` 围栏内，围栏外只留一到两句说明。
- **允许字符集**：ASCII；中文及全角标点；U+2500–259F（制表与方块）；U+2800–28FF（盲文）；
  `← → ↑ ↓ ↔ ↕ ⇐ ⇒ ⇔ ■ □ ▪ ▫ ● ○ ◆ ◇ ▲ △ ▼ ▽ ▶ ▷ ◀ ◁ ▸ ▾ • · … ✓ ✗ ★ ☆`。
- **禁止 emoji**（宽度不定，会错位）与 **ANSI 颜色码**。

## 宽度规则

- 中文与全角标点按 **2 列**计；其余允许字符按 **1 列**计。
- 每行用**空格**补齐，同一方框内各行显示宽度一致；方框四角与竖线列号对齐。
- 推荐每行显示宽度 ≤ 80 列，避免渲染时换行。

## 画完必须校验

把字符图写进临时文件，运行校验脚本，有错误就改到通过再输出。**不要手数空格。**

```sh
node <技能实际目录>/diagram-check.mjs diagram.txt      # 读文件
node <技能实际目录>/diagram-check.mjs -                  # 读 stdin
node <技能实际目录>/diagram-check.mjs --json diagram.txt # 机器可读结果
```

校验项：允许字符集；行显示宽度；**笔画连通**（每个角与交叉点的各笔画方向都要接上相邻格，纯直线两端可开放，箭头视为端点；断开时写明行、列、字符与方向）；方框边框完整；框外字符；无框多栏的**列错位**（右栏起始列相差 1–2 列即报）。退出码：无错 `0`，有错 `1`。

`references/patterns.md` 有每种图的中文示例（均通过校验），不确定排版时先参考。
