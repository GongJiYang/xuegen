# 课程、计划与收课

负责学习状态，教学交给 `teach`，知识整理和闪卡交给 `wiki-save`，只读展示交给 `course-board`。不自动制卡、不创建第二套进度存储、不依赖终端界面。直接关闭终端不会触发本技能，不能承诺退出时自动保存。

## 状态文件与只读锁

每门课一个状态文件 `wiki/courses/<course-slug>.md`，是这门课唯一的状态来源；`wiki/courses.md` 是由脚本从这些文件生成的看板。文件夹里不另建 daily、progress、plans、数据库或每课子目录。

状态文件默认只读（0444），`wiki/courses/` 目录为 0555：人改不了、删不掉，脚本和 AI 需要时才临时放开。这是防误改，不是权限边界——AI 与用户同一系统账号，用户解锁后仍能改；看板校验会发现不一致并报告，不静默接受被人改过的状态。

写入路径固定为「解锁 → 编辑状态文件 → 生成截图（如需）→ 上锁 → 刷新看板」，用本技能同目录的 `course-state.mjs`：

```sh
node "<技能实际目录>/course-state.mjs" verify "<绝对路径>/wiki/courses" "<绝对路径>/wiki/courses.md"   # 写入前先看锁与一致性
node "<技能实际目录>/course-state.mjs" unlock "<绝对路径>/wiki/courses/ctm.md" "<绝对路径>/wiki/courses"
# …这里用编辑工具做局部修改…
# …需要截图时在解锁期间用本技能同目录的 render-snapshot.mjs 生成…
node "<技能实际目录>/course-state.mjs" lock "<绝对路径>/wiki/courses/ctm.md" "<绝对路径>/wiki/courses/ctm-2026-10-16-01.png" "<绝对路径>/wiki/courses"
node "<技能实际目录>/course-state.mjs" dashboard "<绝对路径>/wiki/courses" "<绝对路径>/wiki/courses.md"
```

`lock` 对文件设 0444、对目录设 0555，所以上锁时把本次改动的状态文件、新生成的截图和课程目录一起传进去，`wiki/courses/` 里的东西全都不再可写。上锁前若还缺一步（比如截图没生成），先别锁。

- 只改已有文件、不出图时，解锁状态文件即可；要新建课程或新建截图时必须同时解锁目录。
- 编辑工具或渲染脚本报 `EACCES` 就是还没解锁，按上一步补齐；不要为了绕过锁改用别的命令写文件。
- 任一步失败就停下如实报告，不要把部分写入说成完成；写入失败时保持原文件的锁状态。
- `verify` 报出「目录可写」「缺少标记」「看板过期」等，说明人工改过或上次写入没收尾，先报告再按上面流程修好。

## 定位课程

1. 阅读 `../wiki-save/SKILL.md`，只复用其“入口与配置”中的个人配置定位、Wiki 路径检查及原有规则读取。本操作不因此进入资料摄取或制卡流程。只读/预览不创建任何文件，也不更新日志或时间戳。
2. 优先使用用户明确指定的课程页，或本会话已明确选中的课程。否则根据索引和 `wiki/courses/` 定向寻找匹配项；多个匹配时列出候选请用户选择。无明确课程且只有一门时可选用并告知；没有匹配时询问目标，除非用户已要求创建。不能用最近修改时间决定课程，不能建立跨会话共享的 active-course 指针。
3. 新建课程必须有用户的创建/绑定请求。课程状态文件存为 `wiki/courses/<course-slug>.md`，文件名用 kebab-case。一个课程只建一个文件。若库里已有别的课程组织方式，不要另建一套：说明现状并沿用；规则明确禁止此位置或结构时，说明冲突，不改原规则。
4. 课程页是学习项目页：沿用库内实体页结构，添加必要的计划和记录段落，不另加一套必填元数据。材料只登记实际存在的位置、已知版本及阅读范围；库内用 WikiLinks，外部链接遵从库规范。绑定材料不等于全文已读或完成 Ingest，不搬动 raw、整本教材或聊天档案。不知道版本、页码或当前章节时标为未确认，不编造。

## 一页的结构

沿用已有页面和人工内容，以下是新建页面的结构示例，不要把示例任务或结果当成用户已经完成的事实。各段使用库内一致的标题；不要为排版另建模板文件。

```markdown
<!-- xuegen:course-state — 本文件由 AI 维护（只读锁 0444）。请勿手工编辑。-->

# 课程名称

## Overview
学习目标，以及使用的书籍或资料范围。

## Key Facts
- 当前周：未确认
- 课程 slug：course-slug
- 阅读位置：未确认（阅读进度不代表理解程度）

## Relationships
已存在的相关概念或笔记链接；没有时不制造空链接。

## Sources
实际绑定的教材、资料或相关来源页。

## Overall Goals
总目标与验收条件；用少量可核实的里程碑表示，不把整本书页数当作掌握率。
- [ ] 一个总目标里程碑

## This Week
W1 · 本周主题｜日期范围：未设定
- [ ] 本周活动（完成条件：可观察的结束条件）

## Today
日期：YYYY-MM-DD
- [ ] 一个具体活动（完成条件：可观察的结束条件）

## Next Session
下次的第一个具体动作。

## 计划表（参考，不带复选框）
多周/多阶段的完整路线。这里只做参考，勾选只出现在上方 Overall Goals / This Week / Today 三区。

## Learning Record
收课时才追加实际证据，不预填结果。
```

首行的 `xuegen:course-state` 标记是脚本识别状态文件的依据，不要删除或改写。`Key Facts` 里的「- 当前周：」也是看板读取的字段，换周时同步更新。

- 勾选只出现在 `Overall Goals` / `This Week` / `Today` 三个区；`计划表` 里的任务不带复选框，避免同一件事有两份状态。
- `Overall Goals` 是里程碑（数量少、可核实），不是把周任务抄一遍。
- 课程页是唯一的课程状态来源；配置只绑定 Wiki 路径。`wiki/index.md` 是目录，不复制计划或进度。新建课程时登记到索引的 `## Courses` 区域，避免孤立页面；同一课程不重复登记；若库里还没有该区域，按库内既有排版风格补一个。课程页过长时先保持本次改动局部，用户要求整理后再归档，不自动分裂成每天一份文件。截图是可重建的输出，不从图片反向维护进度，也不持久保存第二份报告 JSON 或 HTML。

## 制定与开始学习

- 根据用户目标、可用时间、教材结构和现有证据形成粗路线；今天只安排 2–3 项活动，用户指定数量时遵从。不重做已经有答案的基础调查，也不为创建计划强制一轮测验。
- 尚未开始学习也要把已有计划的第一项写成 `Next Session` 的具体起点；不使用“暂无”“待开始”替代已有下一步。仅创建课程但尚无计划时，如实写明需要确认的目标或材料位置。
- 每项任务明确结束条件。比如“尝试证明并完成订正”可以在提示后完成；“无提示独立证明”必须有独立作答证据。仅听过讲解不能完成独立作答任务。
- 复选框只统计活动完成情况，不计算掌握百分比。阅读位置、练习结果分开记录。结果使用“独立完成 / 提示后完成 / 仍有错误 / 未验证”，必要时标注“用户自报，未检查”。
- 只要求预览计划时在回复中展示，不写文件。明确要求制定并保存计划、绑定课程时可直接写入，不逐页重复确认。
- 换日或调整计划前，保留旧计划的日期、任务和结果，不重置或丢弃历史。未完成任务明确保留、延期或记录取消原因；不能为了多打勾而偷偷降低原条件。
- 周目标与总目标沿用已约定计划，不为截图临时发明目标、起止日期或完成比例。总目标的里程碑必须满足对应验收条件才能完成；当天听完讲解不代表本周完成。已有计划的周标题和任务列表可直接沿用，不为展示重排整份文档。发现计划覆盖不足以达成总目标时标注缺口，不静默修改目标。
- 开始或继续时，用几行显示课程、当前位置、活动完成数和下一步，再按 `teach` 教学。单纯查看进度不启动教学，不标记任务完成。切换自由话题不继续给原课程记账。

## 收课：打勾与抵消

用户在已选课程中说“今天学到这里”“更新进度”“把今天的勾打一下”等，就是本次收课写入请求；说“抵消/撤销某个勾”是撤销请求；没有已选课程时先定位，不能凭空新建。用户说“本次不记录”时不写入。按以下顺序执行：

1. 重新读取课程页，检查用户的手改和已有记录。依据当前实际可见的作答、提示及订正核对原任务条件；不从模型自己的讲解推断用户已经作答。上下文丢失或历史未读时保留未知，不补写不存在的表现，也不自动搜索私人会话档案。
2. **打勾**：只有满足原条件的任务改为 `[x]`，并链接到本次记录标题；否则保持 `[ ]` 并简述原因。仅有用户自报时注明自报，不能声称检查过；用户手动勾选也不自动产生“独立完成”的证据。
3. **抵消（撤销）**：把该任务退回 `[ ]`，看板数字随之下降。撤销不删除历史——在本次记录里写明原来勾选的时间、撤销原因，以及这是按用户要求做的。若核对后发现条件其实已满足，先说明依据并请用户确认，不擅自改回或保留。
4. 未完成的活动保持 `[ ]` 并注明原因（延期 / 取消 / 仍有错误）；不因为“今天结束了”默认勾选，也不把当天没做的事悄悄从计划里删掉。
5. 向 `Learning Record` 追加一条简短记录，标题使用本机日期和当天序号（如 `### 2026-10-16-01`），已有标题不能复用给另一轮练习。记录原任务及其条件、题目、用户必要的原答片段、提示/订正、结果和下一步。不要抄整段聊天。保留错误作答以便追溯；评价是可纠正的解释，不能改写原答来迎合评价。
6. 更新必要的当前位置与 `Next Session`，保留绑定资料、人工备注和既有记录。阅读位置只在实际读到或用户确认时更新。重复收课先比较已有题目、原答及结果；没有新证据或计划变化时说明“已记录”，不要再次追加记录、重打勾或更改日期。后续有新作答则是新记录，不能抹掉之前的错误。换周时把新一周的活动移到 `This Week`，旧周任务必须先有记录或注明未完成，不能直接消失。
7. 仅作局部编辑，不整页重写。写入前以最新文件为准；遇到并发改动先合并或报告，不能覆盖人工修改。写入严格按「状态文件与只读锁」一节的顺序：解锁 → 编辑 → 生成截图 → 上锁（状态文件 + 截图 + 目录）→ 重新生成看板；截图不要留到上锁之后做。课程页变更按原规则追加 `wiki/log.md`，用 `course | 课程名` 说明本次变更；只查询或重复无变化时不写日志。不要把课程收课伪装成 Ingest 或顺带改概念页、闪卡和原规则。
8. 保存后核对：打勾项有真实依据，链接/标题存在，原记录和手改保留，未生成重复记录，状态文件已回到只读、看板与状态一致。简短报告哪些活动完成、哪些仍需练习、下次起点，以及实际保存路径和看板当前数字。只有写入成功才说“已保存”。若部分写入失败，准确报告已完成和失败的部分，下次先对照页面补齐，不声称整体成功。
9. 完成有新内容的收课后，按下节在解锁期间生成带日期的 PNG（生成后与状态文件一起上锁），并在本条记录中嵌入图片链接。普通只读查询和重复无变化的收课不生成新图片；原图片缺失或上次渲染失败时可补生成（补生成同样先解锁目录）。用户明确要求截图演示时允许只生成图片，不更新学习状态。

## 日期截图

截图展示课程、报告日期、总目标、本周任务和总目标里程碑的完成数、真实作答证据、下次起点。完成数由脚本计算，标签说明统计粒度；没有目标时显示“尚未设定”，不显示虚假的 0% 或掌握率。某模块已有讲解/作答但未满足验收条件时，既保持未勾选，也在证据区说明已经做过什么。

使用本技能同目录的 `render-snapshot.mjs`，通过标准输入传入临时 JSON。`source` 是已经保存的课程/计划 Markdown 的绝对路径；脚本不修改它。不需要额外 npm 依赖，使用本机 Chrome/Chromium；非默认安装位置可设置 `CHROME_PATH`。

```sh
node "/技能实际目录/render-snapshot.mjs" "/课程目录/course-slug-YYYY-MM-DD-NN.png" <<'REPORT'
{
  "title": "课程名称 · 收课记录",
  "date": "2026-10-16",
  "source": "/实际课程路径/course.md",
  "goal": "已经与用户约定的总目标",
  "week": {"label": "W1 · 本周活动", "tasks": [{"label": "原计划任务", "done": false, "detail": "尚未满足原验收条件"}]},
  "overall": {"label": "全程里程碑", "tasks": [{"label": "原计划里程碑", "done": false}]},
  "evidence": ["真实作答片段或核实结果，不能把示例当事实"],
  "next": "从已有记录确定的下一步",
  "note": "必要时说明证据范围、未知项或计划缺口"
}
REPORT
```

上述路径、日期和内容均须替换。`done` 只接受布尔值，不传字符串；从已保存的原任务/验收结果逐项提取。核对源文件后才调用，不把模型刚生成但未保存的计划当来源。截图日期是实际收课/报告日期；复盘旧会话时另外在证据中注明原会话日期，不能伪装为当天新学。

默认图片与课程文件同目录，以课程名、日期、记录序号命名，避免额外文件夹。若 Wiki 已规定可写附件位置则沿用，绝不写入只读 `raw/`。生成成功后确认脚本退出码为 0、PNG 存在，把它和状态文件一起用 `lock` 上锁（脚本对文件设 0444），再用库内相对链接嵌入对应记录，例如 `![[course-slug-YYYY-MM-DD-NN.png|600]]`，并在回复中给出图片路径。已有图片不会被覆盖；重复收课直接引用已有图片。未安装浏览器或渲染失败时，保留已保存的 Markdown，明确说明“进度已保存，截图失败”及原因，不谎报截图完成，不自动安装软件。

这些是模型执行的工作约定，加上一层防误改的只读锁；不是权限边界，也不是学习能力认证。AI 与用户同一系统账号，用户解锁后仍能手工改，看板校验只能发现并报告不一致。后续界面读同一份 Markdown 与 `wiki/courses.md` 看板，不另维护网页状态，也不提供人工修改入口。
