# 课程、计划与收课

负责学习状态，教学交给 `teach`，知识整理和闪卡交给 `wiki-save`，只读展示交给 `course-board`。不自动制卡（排期标记含 `reviews=anki` 的课程在收课时先提议卡片，用户确认后才写入，见「收课」第 10 步）、不创建第二套进度存储、不依赖终端界面。直接关闭终端不会触发本技能，不能承诺退出时自动保存。

## 状态文件与只读锁

每门课一个状态文件 `wiki/courses/<course-slug>.md`，是这门课唯一的状态来源；`wiki/_generated/courses.md`（旧库：`wiki/courses.md`） 是由脚本从这些文件生成的看板。文件夹里不另建 daily、progress、plans、数据库或每课子目录。

状态文件默认只读（0444），`wiki/courses/` 目录为 0555：人改不了、删不掉，脚本和 AI 需要时才临时放开。这是防误改，不是权限边界——AI 与用户同一系统账号，用户解锁后仍能改；看板校验会发现不一致并报告，不静默接受被人改过的状态。

**课程会话里对课程页、概念页的一切写入（收课、存档点、开课时给讲后读打勾）都只经 `course_close` 工具**（见「收课」与 `references/close.md`），不用下面的解锁路径。下面的路径只用于总控会话里新建课程、改计划。开课时的顺延在课程会话里用 `course_close` 的 `shift`（见「逐日排期」）。

写入路径固定为「解锁 → 编辑状态文件 → 生成截图（如需）→ 上锁 → 刷新看板（Markdown + 网页）」，用本技能同目录的 `course-state.mjs` 与 `render-board.mjs`：

```sh
node "<技能实际目录>/course-state.mjs" verify "<绝对路径>/wiki/courses" "<绝对路径>/wiki/_generated/courses.md"   # 写入前先看锁与一致性
node "<技能实际目录>/course-state.mjs" unlock "<绝对路径>/wiki/courses/ctm.md" "<绝对路径>/wiki/courses"
# …这里用编辑工具做局部修改…
# …需要截图时在解锁期间用本技能同目录的 render-snapshot.mjs 生成…
node "<技能实际目录>/course-state.mjs" lock "<绝对路径>/wiki/courses/ctm.md" "<绝对路径>/wiki/courses/ctm-2026-10-16-01.png" "<绝对路径>/wiki/courses"
node "<技能实际目录>/course-state.mjs" dashboard "<绝对路径>/wiki/courses" "<绝对路径>/wiki/_generated/courses.md"
node "<技能实际目录>/render-board.mjs" "<绝对路径>/wiki/courses" "<绝对路径>/wiki/_generated/courses.html"（旧库：`wiki/courses.html`）   # 只读网页看板
```

`dashboard` 之后一定跑 `render-board.mjs`：网页看板是派生文件，先刷新 Markdown 看板再渲染，页面顶部的校验行才会是「校验通过」。`render-board.mjs` 本身不写任何状态文件，只把 `wiki/courses/*.md` 读出来渲染成一张自包含 HTML（无脚本、无表单、无编辑入口），并对输出文件设 0444；它放在 `wiki/`（0755）而非 `wiki/courses/`，所以重新生成不需要解锁课程目录。

`lock` 对文件设 0444、对目录设 0555，所以上锁时把本次改动的状态文件、新生成的截图和课程目录一起传进去，`wiki/courses/` 里的东西全都不再可写。上锁前若还缺一步（比如截图没生成），先别锁。

- 只改已有文件、不出图时，解锁状态文件即可；要新建课程或新建截图时必须同时解锁目录。
- 编辑工具或渲染脚本报 `EACCES` 就是还没解锁，按上一步补齐；不要为了绕过锁改用别的命令写文件。
- 任一步失败就停下如实报告，不要把部分写入说成完成；写入失败时保持原文件的锁状态。
- `verify` 报出「目录可写」「缺少标记」「看板过期」等，说明人工改过或上次写入没收尾，先报告再按上面流程修好。

## 定位课程

1. 阅读 `../wiki-save/SKILL.md`，只复用其“入口与配置”中的个人配置定位、Wiki 路径检查及原有规则读取。本操作不因此进入资料摄取或制卡流程。只读/预览不创建任何文件，也不更新日志或时间戳。
2. 优先使用用户明确指定的课程页，或本会话已明确选中的课程。否则根据索引和 `wiki/courses/` 定向寻找匹配项；多个匹配时列出候选请用户选择。无明确课程且只有一门时可选用并告知；没有匹配时询问目标，除非用户已要求创建。不能用最近修改时间决定课程，不能建立跨会话共享的 active-course 指针。
3. 新建课程必须有用户的创建/绑定请求。课程状态文件存为 `wiki/courses/<course-slug>.md`，文件名用 kebab-case。一个课程只建一个文件。若库里已有别的课程组织方式，不要另建一套：说明现状并沿用；规则明确禁止此位置或结构时，说明冲突，不改原规则。
4. 课程页是学习项目页：沿用库内实体页结构，添加必要的计划和记录段落，不另加一套必填元数据。材料只登记实际存在的位置、已知版本及阅读范围；库内用 WikiLinks，外部链接遵从库规范。绑定材料不等于全文已读或完成 Ingest。原料只有 `raw/` 一个入口：教材 PDF 在 `raw/books/`，不在时提议复制进去，用户同意后再复制（不移动原文件）；每份材料在 `wiki/knowledge/sources/`（旧库：`wiki/知识/sources/`） 有登记页。课程页 `Sources` 只链接登记页，不写本地绝对路径，不装材料内容。不搬动聊天档案。不知道版本、页码或当前章节时标为未确认，不编造。

## 原书方式与课程骨架（新建或改计划时定）

**原书方式**：每门课在 `Key Facts` 记一行 `- 原书：带读` / `先读后讲` / `边读边讲` / `讲后读（错开）`。**学习周期的主项课一律「讲后读（错开）」**（用户 2026-11-06 定：主项必须读原书），不问、不用带读；用户明确要求改时才改。其他课新建时以用户给出的为准；没给就问一句，用户不在意时用「带读」。改计划时可以改。

- **带读**：学根讲，不安排读原文。课次的资料列只写对应章节作出处。
- **先读后讲**：每个课次先读原书再讲。课次内容写成「读 §x–y（约 N 页）→ 讲与练」；`Today` 里「读原书 §x–y」单独一行、单独打勾（完成条件：读完，并能说出一个要点或疑问）。开课时先问读了没有：没读就先给阅读时间，或这一节临时改成边读边讲；不假装用户读过。
- **边读边讲**：课内一起读原文，学根按段落或页码引原文逐段讲，不单独排阅读行。
- **讲后读（错开）**：主项课专用。课上只讲与练；讲完读这一节的**核心页**，放到**另一门主项的下一个上课日**读（周模板里两门主项交替，如周一离散 → 周二读；周四的课跳过整合日与低强度日，到下周一读）。核心页**在开课时定**：讲之前打开原书这一节（PDF 书签或目录页，页码换算记在 `Key Facts`），挑出本节必读的定义、定理、关键例子和要讲的段落，不含习题；第一条回复里告诉用户核心页是哪几页。读原书按页读（如 `pdftotext -f <起> -l <止>`），一次不超过 10 页，不整章导出，导出的文字不整段打印进对话。排期表「材料」列只写「讲后读核心页（开课时定），下一个 <另一门短名> 日读」，不预先写页码，`shift` 也不用改。收课时在 `Today` 加一行「- [ ] 讲后读 §x–y pp.a–b · YYYY-MM-DD 读」（完成条件：读完，并能说出一个要点或疑问）。下次开这门课时先问那节读了没有、有什么疑问：读完就打勾，记「用户自报，未检查」，并在该书阅读页的 Reading Log 记一行（`reading` 技能的 `note` 命令，如「讲后读 D1 核心页 pp.1–5、7–12 已读（用户自报）」）；没读就保留，不假装读过。核心页之外的内容由该书的通读接着读。
- 除「讲后读（错开）」与「原书通读」外，读原书都在这一节课里，不占别的日子。

**原书通读（主项课）**：整本书另从头读，放在书房（`wiki/shelf/<书>.md`（旧库：`wiki/书房/<书>.md`），见 `reading` 技能「书房」），不写进课程页：每天一段（按节切、≤ 10 页），计划内一次一本、读完再开下一本；讲后读读过的页照读，不跳过。课程页 `Key Facts` 只写一句「原书：讲后读（错开）；通读见 [[shelf/<书>]]（旧库：`[[书房/<书>]]`）」。

**不估时长**（用户 2026-11-06 定）：课次只写当天学什么——章节、页码、要讲的点、完成条件，不写「约 N 分钟」，也不估读完或学完的日期。课次按教材章节切；学习周期规定了每节时长的（主项 90 分钟、辅助 ≤ 45 分钟），切课次时照着取量。收课时按实际学到哪在 Learning Record 记一句，下次排期参考。
- 主项课不写 `阅读位置`（看该书阅读页）；其他课的 `阅读位置` 只在实际读到或用户确认时更新。

**课程骨架**：建课时先找教材目录（PDF 书签、目录页、出版方目录）。找到了就按章节切课次，每个课次的资料列写章节号和页码，不自拟。找不到目录（文章、视频、对话式课题）才自拟大纲、按内容扩展。在 `Overview` 写一行 `骨架：教材目录（Ch1–Ch10）` 或 `骨架：自拟（无目录）`。删减的章节列进计划表的「明确缺口」，不悄悄跳过。

## 一页的结构

沿用已有页面和人工内容，以下是新建页面的结构示例，不要把示例任务或结果当成用户已经完成的事实。各段使用库内一致的标题；不要为排版另建模板文件。段落顺序、完成条件写法和打勾规则另见同目录 `PLAN-STANDARD.md`（标准计划输出，以 `mech-interp` 为例）；网页看板按同一顺序渲染。

```markdown
<!-- xuegen:course-state — 本文件由 AI 维护（只读锁 0444）。请勿手工编辑。-->

# 课程名称

## Overview
学习目标，以及使用的书籍或资料范围。

## Key Facts
- 当前周：未确认
- 课程 slug：course-slug
- 阅读位置：未确认（阅读进度不代表理解程度；主项课不写这一行）
- 原书：带读（主项课写「原书：讲后读（错开）；读到哪见 [[reading/<书>]]」）

## Relationships
已存在的相关概念或笔记链接；没有时不制造空链接。

## Sources
实际绑定的教材、资料或相关来源页。

## Overall Goals
总目标与验收条件；用少量可核实的里程碑表示，不把整本书页数当作掌握率。
- [ ] 一个总目标里程碑

## This Week
W1 · 本周主题｜日期范围：未设定
- [ ] 本周活动（完成条件：可观察的结束条件）

## Today
日期：YYYY-MM-DD
- [ ] 一个具体活动（完成条件：可观察的结束条件）

## Next Session
下次的第一个具体动作。

## 计划表（参考，不带复选框）
多周/多阶段的完整路线。这里只做参考，勾选只出现在上方 Overall Goals / This Week / Today 三区。

## Learning Record
收课时才追加实际证据，不预填结果。
```

首行的 `xuegen:course-state` 标记是脚本识别状态文件的依据，不要删除或改写。`Key Facts` 里的「- 当前周：」也是看板读取的字段，换周时同步更新。

- 勾选只出现在 `Overall Goals` / `This Week` / `Today` 三个区；`计划表` 里的任务不带复选框，避免同一件事有两份状态。
- `Overall Goals` 是里程碑（数量少、可核实），不是把周任务抄一遍。
- 课程页是唯一的课程状态来源；配置只绑定 Wiki 路径。`wiki/index.md` 是目录，不复制计划或进度。新建课程时登记到索引的 `## Courses` 区域，避免孤立页面；同一课程不重复登记；若库里还没有该区域，按库内既有排版风格补一个。**课程页有上限（约 200 行）**：`Learning Record` 只放收课与周核实的记录；改计划不在这里写记录，只在 `wiki/log.md` 记一条 `course`。课程页不重复周期页已有的内容（周期起止、课次总数、上课星期），写一句链接 [[cycles/cN]] 即可。收课后若 `Learning Record` 超过 2 条收课记录，把更早的整条移到 `wiki/courses/<slug>/records/YYYY-MM.md`（按记录日期的月份，追加在末尾，原文不改），在 `Learning Record` 开头留一行「- 归档：YYYY-MM 的收课记录见 [[courses/<slug>/records/YYYY-MM]] · 完成：D1、D2…」——完成行必须照抄被移走记录里的全部课次 id，脚本靠它判断已完成。归档在收课的暂存目录里做（当月 records 文件 `stage` 已复制进来，没有就在暂存里新建），随 `commit` 一起提交和上锁。不分裂成每天一份文件。截图是可重建的输出，不从图片反向维护进度，也不持久保存第二份报告 JSON 或 HTML。

## 制定与开始学习

- 根据用户目标、可用时间、教材结构和现有证据形成粗路线；今天只安排 2–3 项活动，用户指定数量时遵从。不重做已经有答案的基础调查，也不为创建计划强制一轮测验。
- 尚未开始学习也要把已有计划的第一项写成 `Next Session` 的具体起点；不使用“暂无”“待开始”替代已有下一步。仅创建课程但尚无计划时，如实写明需要确认的目标或材料位置。
- 每项任务明确结束条件。比如“尝试证明并完成订正”可以在提示后完成；“无提示独立证明”必须有独立作答证据。仅听过讲解不能完成独立作答任务。
- 复选框只统计活动完成情况，不计算掌握百分比。阅读位置、练习结果分开记录。结果使用“独立完成 / 提示后完成 / 仍有错误 / 未验证”，必要时标注“用户自报，未检查”。
- 只要求预览计划时在回复中展示，不写文件。明确要求制定并保存计划、绑定课程时可直接写入，不逐页重复确认。
- 换日或调整计划前，保留旧计划的日期、任务和结果，不重置或丢弃历史。未完成任务明确保留、延期或记录取消原因；不能为了多打勾而偷偷降低原条件。
- 周目标与总目标沿用已约定计划，不为截图临时发明目标、起止日期或完成比例。总目标的里程碑必须满足对应验收条件才能完成；当天听完讲解不代表本周完成。已有计划的周标题和任务列表可直接沿用，不为展示重排整份文档。发现计划覆盖不足以达成总目标时标注缺口，不静默修改目标。
- **概念页在收课时写**（用户 2026-11-08 定，开课不写文件，免得讲课前空等）：开课时第一条讲解回复以「今日要点」框开头（格式见 `teach`），主项课再写明核心页，然后直接讲。收课时把要点框里的术语和讲解中新出现的核心术语（4–8 个，辅助课 2–4 个）按 `references/concept-page.md` 的样子写进本次收课的暂存目录（随收课一起提交，见「收课」）：一个术语一页，放在该科目的概念目录（如 `wiki/knowledge/concepts/discrete-math/`（旧库：`wiki/知识/concepts/math/`）），已有同名或同义页就补充、不重建；frontmatter 写 `sources:`（教材登记页链接加节与页码），正文注明课程与课次，定义用自己的话写；写完更新索引与 `wiki/log.md`（类型用 `wiki`）。照样例写，不去库里翻别的概念页找格式。用户说「今天不写库」时跳过。
- **开课先看这门课在周期里的角色**：运行 `cycle-plan` 目录的 `cycle.mjs day "<库根>" --json`，看 `roles[<slug>]`。是 `aux`（辅助课）就按辅助上：这一节 ≤ 45 分钟，按「概览、术语、地图」讲，不出「检查理解」题，今日要点只写 2–4 个术语（概念页同样 2–4 页），收课只记读到哪和疑问，不打独立作答类的勾、不提议卡片。是 `main` 或不在周期里，按常规上。
- **以文件为准，不凭会话记忆**：开课、继续、对照计划、回答「学到哪 / 还剩什么」、改计划之前，都先重新读课程页——本会话第一次读整页，之后只读要用的段落（`Today`、`Next Session`、排期表等，用 `grep -n` 定位再 `sed -n` 读那几行），改完不整页重读；会话里记得的旧计划、旧课次切分一律作废，发现和记忆对不上时按文件说，不说「内容被吃掉了」之类的话。用户消息开头带「[课程页或技能可能已更新…]」时，先整页重读课程页和这次要用的技能 SKILL.md 再回答。同一会话里技能读过一次就不再全文重读；`wiki/log.md` 只读末尾（`tail`），不读全文。
- **讲解偏好（记忆分层）**：开课时读 `wiki/profile.md`（全局）和这门课科目页的 `## 讲解偏好`，只读本科目的，不读、不写其他科目页的偏好。冲突时窄的优先：本会话的要求 > 课程页 `Key Facts` > 科目偏好 > 全局。用户说「以后讲<科目>都…」时，提议一行偏好，确认后写进科目页 `## 讲解偏好`（与旧行冲突就原地替换，行末带日期，全节不超过 15 行）；说「这次…」只在本会话照做，不写文件。`profile.md` 只在用户明确要求时写。课程页不写「讲解风格」行，默认风格在科目偏好里。
- **长会话先存档**：界面提示上下文快满、或用户说要换个会话接着上时，先用 `course_close` 做一次小事务（`stage` → 只改暂存课程页的 `Next Session` 写存档点：当前题目原文、用户答到哪一步、下一步讲什么 → `check` → `commit` 带 `label: "存档点"`，jj 记「存档点」，撤销收课不会撤它），再请用户开新会话；新会话从存档点接着上，收课时把存档点换成正常的下一步。不靠自动压缩保存任何东西。
- **一门课一天一个会话**：开课时如果这个会话里已经是别的课程，或者已经上过更早日期的课，先停下，告诉用户「这是 <日期> 的 <课> 会话，请从「今天」点开课，开今天的新会话」，不在这里接着开新课次。
- 开始或继续时，用几行显示课程、当前位置、活动完成数和下一步；如果存在上一条学习记录，先用一个简短提取问题回忆上次的关键关系，再按 `teach` 教学。单纯查看进度不启动教学，不标记任务完成。切换自由话题不继续给原课程记账。

## 开课顺序

每节课开头按这个顺序做，细节见上下文各条；任何一步报错就停下如实说，不跳过：

1. 确认这是今天这门课的会话（「一门课一天一个会话」）。
2. 整页读一次课程页；读 `wiki/profile.md` 与本科目页 `## 讲解偏好`（「讲解偏好」）。
3. 有排期标记时，调 `course_close`：`action: "shift"`、`slug`、`today: <今天>`（周期课标记里还没有 `end=` 时加 `end: <周期最后一天>`），有变化说一句（「逐日排期」）。
4. `cycle.mjs day` 看这门课是主项还是辅助（「开课先看这门课在周期里的角色」）。
5. 上过课的：问上次的讲后读读了没有（主项课，读了就打勾并 `note`；打勾留到这次收课的事务里一起写，不单独写课程页），再出一个回忆上次关键关系的提取题。它代替 `teach` 的开场诊断，不再另做一轮诊断。第一次上的课才按 `teach` 诊断。
6. 主项课：打开原书这一节定核心页（按页读，一次不超过 10 页）。
7. 第一条讲解回复以「今日要点」框开头；主项课再写明核心页。开课不写概念页（「概念页在收课时写」）。
8. 按 `teach` 讲。

## 学习周期里的课（主项 / 辅助）

新建或改计划时，**先查这门课属不属于当前学习周期**：用 `cycle-plan` 技能目录的 `cycle.mjs overview "<库根>" --json` 看 `cycle.subjects`（模板里的科目）、`cycle.auxSubjects`（辅助列的科目）、`cycle.subjectDays`（每个科目在模板里是周几）和 `cycle.end`。课程的资料属于其中某个科目（看科目页），或请求里写明了「C1 主项 / C1 辅助」，它就是周期课，排期**一律服从周期**，不照表单的开始日、截止日、休息日：

- **上课日**：`--days` 只用这个科目在模板里的那几天（如辅助「C 与系统编程」= 周一、周三）。同科目已有别的周期课时，和用户商量怎么分这几天，不能同一天两门。
- **范围**：`--start` 取今天或之后的第一个上课日，`--end` 取周期最后一天，`--reviews anki`。
- **主项课**：原书方式固定「讲后读（错开）」；通读放进书房（`reading` 技能「书房」，计划内按 `order` 排队）。
- **辅助课**：只做了解——每节 **≤ 45 分钟**，不出检查题、不做周核实、不参加周期验收，收课只记读到哪和问题；内容按「概览、术语、地图」写，不深挖。
- **排不下**：课次多于周期内的上课日时，不压缩、不加天：周期内排满，剩下的列进计划表「留到下个周期」一节（辅助科目下个周期通常就是主项）。告诉用户周期内能学到哪里。
- 建好后在科目页这条资料行末尾补 `→ [[courses/<slug>|短名]]`（短名 2–4 个字，日历格子会显示它），并把行首记号与状态改为「○ 已排期」；开课后改「● 学习中」，学完改「✓ 已完成」（库规则 ◌ → ○ → ● → ✓）。再跑 `cycle.mjs check`，零问题才算完成。
- **主项课**按周写周核实项：`This Week` 里每周一条「周核实 Wn · 日期（整合日）」，完成条件写清要独立回答什么。辅助课不写。
- 不属于任何周期科目的课（路线外）才按表单的开始日、截止日、休息日排。

## 逐日排期（日期只由脚本算）

新建课程、改计划、改截止日期或休息日时，**不手写日期**：模型只列课次，日期交给本技能同目录的 `course-schedule.mjs`。

```sh
S="<技能实际目录>/course-schedule.mjs"; F="<绝对路径>/wiki/courses/<slug>.md"
# 1. 把课次按学习顺序写到临时文件（只给内容，不给日期）：[{"id":"D1","content":"…","material":"…","done_when":"…"}]
# 2. 先预览，再在解锁期间写入（--write 只替换计划表里 xuegen:schedule 标记之间的表格）
node "$S" plan "$F" --start 2026-11-04 --end 2026-12-01 --rest sun --lessons <临时文件> [--write]
node "$S" plan "$F" --start 2026-11-05 --end 2026-12-23 --rest sun --days mon,wed --lessons <临时文件> [--write]   # 只在周一、周三上新课
node "$S" plan "$F" --start 2026-11-06 --end 2026-12-24 --rest sun --days mon,wed --extra 2026-11-06 --reviews anki --lessons <临时文件> [--write]   # 复习交给 Anki；11-06 额外上一课
node "$S" shift "$F" --today <本机今天> [--end <周期最后一天>] [--write]     # 没学的新课顺延到下一个上课日，过期复习挪到今天
node "$S" next "$F" --date <日期> --json             # 某天的安排
```

- `--days` 指定上新课的星期（默认所有非休息日；不能包含休息日）：每个上课日一个新课次，空出的上课日是「机动」。每个课次在学完后第 1、3、7、14 天各有一次简短复习，复习可落在任何非休息日（落在休息日顺延到下一天，超过截止日期的标「课后复习」）。`--days` 记在排期标记里（`days=mon,wed`），之后的 shift 自动沿用。学习周期规定了本科目的深度日时，`--days` 就用那几天。
- `--reviews anki`：计划表不排复习行，复习全部交给 Anki（主项课的卡片在收课时提议，见「收课」第 10 步；辅助课不提议）；默认 `spaced` 才排 +1/3/7/14 天复习。`--extra` 给出周模板之外的额外上课日（逗号分隔，须在起止日期内、不是休息日），只影响这一次排期。`reviews=anki` 记在排期标记里，之后的 shift 自动沿用；extra 不记录。
- 课次多于上课日时脚本会报错并给出「建议截止日期」：如实告诉用户，让用户选延后截止日期还是删减内容，不要擅自压缩课次。
- **开始今天的学习时**，先调 `course_close` 的 `shift`（`slug`、`today: <本机今天>`；它一步完成暂存、顺延、校验、提交，jj 记「顺延」；没有要顺延的什么都不写）；不要在课程会话里 unlock 后跑 `course-schedule.mjs shift --write`。**顺延的结果照单接受**：没学的课整体后推是设计如此；课程会话里不手改排期表的日期，也不为改日期开收课事务。用户对排期有异议，说明情况，请用户回总控改计划。有变化就用一句话告诉用户「没学的新课顺延了 N 个上课日（最后一节 X），M 条过期复习挪到今天」，再开始教学。没有排期标记的旧课程跳过这一步。
- **顺延不越过周期结束日**：`plan --end` 把结束日记进排期标记（`end=YYYY-MM-DD`），之后的 `shift` 自动沿用；标记里没有 `end=` 的周期课（11-10 之前排的），`shift` 时加 `end`/`--end <周期最后一天>`（周期页 `cycles/cN.md` 的起止日期），写入后标记就带上了。顺延后落在结束日之后的新课移出排期表，追加到计划表「留到下个周期」一节，脚本会多输出一句「N 节排不进本周期，已移到「留到下个周期」：…」，照转告用户。
- 收课时在本次 Learning Record 里写一行 `完成：D3、R1-D2`（用计划表「天」列的 id），脚本靠这一行判断哪些已完成；没完成的不写。
- 写入仍按「状态文件与只读锁」的顺序：unlock → `course-schedule.mjs … --write` → lock → dashboard → render-board。脚本报「只读」就是还没解锁。
- 旧课程（计划表没有排期标记）要按天排期时，用户说一句截止日期即可：列出剩余课次后用 `plan` 写入，原来的人工计划内容保留在标记之外。

## 周核实（整合日）

用户在整合日点「核实 →」或说「做本周周核实」时，读同目录 `references/weekly-check.md` 照做；只对主项课做。

## 收课：打勾与抵消

用户在已选课程中说“今天学到这里”“更新进度”“把今天的勾打一下”等，就是本次收课写入请求；说“抵消/撤销某个勾”是撤销请求；没有已选课程时先定位，不能凭空新建。用户说“本次不记录”时不写入。按以下顺序执行。**一次事务写完**：收课只经 `course_close` 工具（用法与校验规则见 `references/close.md`）——`stage` 开一个暂存目录（课程页、当月 records、`wiki/index.md`、`wiki/log.md` 已复制进去）→ 在暂存目录里改这次要改的全部内容（课程页的勾、记录、`Today`、`Next Session`，概念页，索引与日志；要补充的已有概念页先 `add` 复制进来，新页直接写到暂存目录里对应的库内路径）→ `check` → `commit`。正式的库在 `commit` 之前一个字都不动；不 unlock、不 lock、不直接写库里的课程页和概念页（权限上也写不进）。记录格式照 `references/record.md`，不读脚本源码推断格式。

0. **先看这个会话里有没有上过课**：只看本会话里实际可见的讲解和用户作答。一句都没讲过（只有开课请求、没有回答，或回答没有讲课内容）时，直接回一句「这节课还没讲，没有可收的」，不读原书、不定核心页、不写任何文件，到此结束。用户说的是另一个会话里上过的课时，请用户回到那个会话收课。
1. 重新读取课程页，检查用户的手改和已有记录。依据当前实际可见的作答、提示及订正核对原任务条件；不从模型自己的讲解推断用户已经作答。上下文丢失或历史未读时保留未知，不补写不存在的表现，也不自动搜索私人会话档案。
2. **打勾**：只有满足原条件的任务改为 `[x]`，并链接到本次记录标题；否则保持 `[ ]` 并简述原因。仅有用户自报时注明自报，不能声称检查过；用户手动勾选也不自动产生“独立完成”的证据。
3. **抵消（撤销）**：把该任务退回 `[ ]`，看板数字随之下降。撤销不删除历史——在本次记录里写明原来勾选的时间、撤销原因，以及这是按用户要求做的。若核对后发现条件其实已满足，先说明依据并请用户确认，不擅自改回或保留。
4. 未完成的活动保持 `[ ]` 并注明原因（延期 / 取消 / 仍有错误）；不因为“今天结束了”默认勾选，也不把当天没做的事悄悄从计划里删掉。
5. 向 `Learning Record` 追加一条简短记录，标题使用本机日期和当天序号（如 `### 2026-10-16-01`），已有标题不能复用给另一轮练习。课程有逐日排期时，记录里加一行 `完成：<计划表 id>`（见「逐日排期」）。记录原任务及其条件、题目、用户必要的原答片段、提示/订正、结果和下一步。不要抄整段聊天。保留错误作答以便追溯；评价是可纠正的解释，不能改写原答来迎合评价。
  - Learning Record 保留本次是否做过主动提取、是否使用提示、是否完成迁移题，以及仍待核实的知识点；这些是学习证据，不是额外的掌握百分比。没有实际作答时写“未验证”，不从讲解内容推断完成。
6. 更新必要的当前位置与 `Next Session`，保留绑定资料、人工备注和既有记录。阅读位置只在实际读到或用户确认时更新。重复收课先比较已有题目、原答及结果；没有新证据或计划变化时说明“已记录”，不要再次追加记录、重打勾或更改日期。后续有新作答则是新记录，不能抹掉之前的错误。换周时把新一周的活动移到 `This Week`，旧周任务必须先有记录或注明未完成，不能直接消失。
7. 仅作局部编辑，不整页重写，改的是暂存目录里的副本。课程页变更按原规则在暂存的 `wiki/log.md` 末尾追加，用 `course | 课程名` 说明本次变更（日志只能追加，`index.md` 只能加行，`check` 会查）；只查询或重复无变化时不写日志。不要把课程收课伪装成 Ingest，也不要顺带改闪卡和原规则。本课的概念页在收课时写（见「概念页在收课时写」），并在日志记一条 `wiki`。有新内容时按第 9 步把截图也生成到暂存目录里。全部改完后 `check`：不通过就按 `problems` 改暂存里的文件再 `check`；报 `conflict`（库里的文件在暂存后被别处改过）时停下告诉用户，`abort` 后重新 `stage` 再做，不硬改。通过后直接 `commit`（不再等用户确认）。`commit` 之后刷新两个看板（`course-state.mjs dashboard` 与 `render-board.mjs`），看板失败只报告，不影响已提交的收课。
8. 提交后核对：打勾项有真实依据，链接/标题存在，原记录和手改保留，未生成重复记录，两个看板与状态一致（只读锁由 `commit` 负责，不手动 lock）。简短报告哪些活动完成、哪些仍需练习、下次起点和看板当前数字；回复最后用一个小标题「这次改了」逐条列出改了哪些页面的哪部分（平实说法，如「离散课程页：D2 打勾、加一条学习记录、写了讲后读」「新建概念页 2 个：真值表、逻辑等价」），不贴命令和路径。用户随后点「撤销这次收课」时，用 `course_close` 的 `undo`：它把这次提交改过的已有文件恢复到收课前；那次新建的页面（概念页、卡片页）保留不删；之后又被改过时它会拒绝，照它的原因告诉用户。撤销后把它列出的新建页面告诉用户，问要不要删，不自动删（Anki 里的卡也不动）。只有 `commit` 返回 `committed: true` 才说“已保存”；`check` 不过或 `commit` 报错时，正式的库没有变，如实说明，不声称保存了。`commit` 报「提交中断」时说明下次运行会自动补完。
9. 完成有新内容的收课后，按「日期截图」（`references/snapshot.md`）把带日期的 PNG 生成到暂存目录里本课的 snapshots 位置（`commit` 前生成，随事务一起提交和上锁），并在本条记录中嵌入图片链接。普通只读查询和重复无变化的收课不生成新图片；原图片缺失或上次渲染失败时可在下一次收课里补生成。用户明确要求截图演示时允许只生成图片，不更新学习状态。
10. **提议闪卡（仅限排期标记含 `reviews=anki` 的课程）**：第 8 步核对保存成功后，从本次记录里**用户已作答并核实**的知识点列出建议卡片（每张写正面、背面、牌组），默认 3–8 张，只在回复里展示，不写文件。用户确认（可删改）后，按 `../wiki-save/SKILL.md`「制作闪卡」与库内 `wiki/prompts/wiki/flashcard-rules.md` 写入；用户说不要就跳过，并说明这次没有制卡、Anki 不会复习今天的内容。没核实过的内容不提议、不制卡；不因为制卡改课程页的勾选。
