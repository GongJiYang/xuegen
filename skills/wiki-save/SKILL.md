# 按需整理学习成果

这是按需查询与整理工作流。默认教学由 teach 负责，课程计划与进度由 course 负责；本工作流不自动归档、不复制完整聊天记录。

## 入口与配置

1. 先区分只读查询/预览与明确保存，再确定范围：查询、整理文档关系、制作闪卡，或后两者。遵从用户已有指示；缺少实际学习内容或范围无法判断时，询问缺失信息，不自行编造课程成果。
2. 使用当前工具读取个人配置：启动器会将 `XUEGEN_HOME` 设置为绝对路径，读取该目录的 `wiki.json`；若在其他宿主中该变量未设置，读取用户主目录下 `.xuegen/wiki.json`。变量存在但不是绝对路径时，请宿主明确配置目录，不随工具工作目录变化重新解释。只查询这一个环境变量，不输出所有环境变量或读取凭据。
3. 配置格式为 `{"root":"知识库绝对路径"}`。确认 root 是存在的目录，路径含空格时正确引用。未配置或无效则请用户指定库位置，不猜测、不创建替代库，也不在应用源码里保存私人路径。
4. 仅在触发本工作流后读取库根目录的 `AGENTS.md`、适用的子目录规则和 `wiki/index.md`。这些规则是维护库时的依据，不修改规则文件或库内原有 skills、prompts。规则缺失或任务与规则冲突时，说明具体冲突并询问，不自创平行规范。

## 只读查询或预览

- 使用索引和定向搜索定位相关页面，按需阅读并引用实际存在的链接。不要扫描整个主目录或加载整个 Wiki。
- 不创建配置、目录或页面，不更新索引、日志或时间戳，不生成闪卡文件。资料不足时如实说明；预览内容只在回复中展示。没有明确保存请求，不进入下面的写入流程。

## 整理文档关系

- 从当前对话提取已核实结论、适用条件、推导、实际阅读的来源和待核实问题；区分用户答案、模型解释和外部来源。
- 根据索引与定向搜索读取相关来源页、概念页、综合分析；优先补充现有页面，避免同义页面。只建立确实有依据的关系，链接应指向存在的目标。
- 用户要求的页面关联必须实际保存为链接，不能仅在回复中描述“内容相关”。涉及概念页与卡片页时，在库规范允许的位置建立关联，卡片链接放在卡片块外；只读来源不强行补反向链接。
- 按库原有约定维护来源、WikiLinks、索引及追加式日志。原文与总结分开；无法证实的引用不写成事实，矛盾明确标注，不能静默抹平。
- 章节精读不等于整篇摄取。保存时明确论文版本、章节/图号及已读范围。若库的正式 Ingest 要求完整阅读，则仅在满足条件后执行；否则提供有明确范围的讨论总结方案。不要把未读全文标为已完成 Ingest。
- 尊重 raw 的只读规则。MCP 下载缓存不自动复制到 raw，不改已有原始资料。不要修改 .obsidian 配置、聊天档案或其他无关文件。

## 制作闪卡

- 仅在用户请求制作闪卡时执行；显式要求不制卡时遵从。若某个既有操作强制制卡而与本次范围冲突，先说明冲突，不擅自修改原规则。
- 读取库内现有制卡规则（此库为 `wiki/prompts/wiki/flashcard-rules.md`），参考目标主题的现有卡片，按原有 note type、牌组、字段和目录规范制作。
- 根据本次有来源支持的知识、易混淆点和推导设计主动回忆题。执行原有数量及格式要求，不自行另定模板；内容不足时如实说明。
- 更新已有卡片时保留 `<!--ID: ...-->`、既有牌组及关联关系；新卡不伪造 ID。不整文件重生成已有卡片，不因表述变化制造重复卡片。
- 写入卡片文件不等于同步 Anki。默认由现有 Obsidian-to-Anki 插件同步；没有实际同步证据时只报告“已生成/更新”，不宣称已同步。

## 保存与返回

- 用户明确要求保存或关联即授权本次范围内写入，无需逐页重复确认。关联概念页与已有卡片意味着补齐页面间实际链接；即使正文相同、索引已有链接，也应完成缺失的页面关联，不以“可以帮你添加，请确认”结束。用户只要求预览、查询或建议时不写文件。
- 只修改本次有关的 Wiki 内容。编辑前重新读取目标；发现自读取后已有变化时，基于最新内容合并，不覆盖其他编辑。文件操作规则是工作约定，不是文件系统沙箱。
- 检查本次新增链接、来源范围、卡片格式及既有 ID 是否保留；不顺带全库重写或修复历史问题。
- 返回简短清单：新增/更新的页面、卡片数量、重要关联、待核实事项和同步状态。
- 不依赖终端按键、CLI 输出解析或 Obsidian 窗口；未来的聊天界面可以提供同样的对话上下文和文件工具调用此工作流。
