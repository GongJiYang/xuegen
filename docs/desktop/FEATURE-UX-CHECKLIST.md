# 功能 UX 检查清单（2026-11-12，用户原稿 `~/Desktop/feature-ux-spec-template.md` 的修订版）

用法：**每做一个界面功能，写任务单时按本清单填「功能卡」和各项要求；验收时逐项打勾，每项写验证方式和结果**。本清单与下面几份文件一起用、不重复它们的细节：
- 用户要求与词表：`docs/desktop/SKIN-LEDGER.md`（G1–G9、第三节词表）——功能事实以它和 `skins/contract.ts` 为准（`FEATURES.md` 已被取代）。
- 视觉数值：`docs/desktop/BEAR-VISUAL-PLAN.md`（变量、对比度、主次、状态补齐、截图对比）。
- 查 bug 流程：`docs/platform/CHECK-PROCESS-1111.md`（用词闸门、跨处一致、`XUEGEN_TODAY`、场景走查）。

## 0. 功能卡（任务单开头必填）

| 字段 | 填写 |
|---|---|
| 功能名 / 用户任务（一句话） | |
| 入口（按钮在哪一屏哪个位置；`/` 只是快捷方式） | |
| 默认状态（打开时看到什么、默认选中什么） | |
| 成功结果（用户看见什么变化） | |
| 数据来源（脚本 / 文件 / 接口；**同一事实还在哪些地方显示**，附 grep） | |
| 会不会改库 / 改 Anki？怎么撤销（10 秒撤销 / jj 撤销 / 不可撤，要确认） | |
| 含不含 AI | 是 / 否 |
| 设计稿（链接 + 屏号）；本批做 / 不做哪几屏 | |
| 契约插槽（`contract.ts`）；bare / chicago 最小实现 | |

## 分级（不是每次都要全过）
- **A 新功能 / 新屏**：全部章节。
- **B 改已有功能的行为**：§1.3 状态、§1.6 撤销、§2 视觉、§3 一致性、§4（若有 AI），再加改到的那几项。
- **C 只改文案或样式**：§1.8 文案、§2 视觉、用词闸门、受影响屏的同宽截图。

每项写成一行：`状态（✓ 做了 / ✗ 没做 / — 不适用 / 不做：理由）· 验证方式（测试名 / 走查断言 / 截图 / 人看）`。**没有验证方式的 ✓ 不算。**

## 1. 通用（依据：NN/g、GOV.UK、APG、WCAG）

### 1.1 入口与可发现
- 常用动作有看得见的按钮；`/` 只是快捷方式（G5）。[NN/g 十条](https://www.nngroup.com/articles/ten-usability-heuristics/)
- 按钮名 = 用户的任务和真实后果（「开课」「收课」「交给总控排」），不用脚本名（G4）。[GOV.UK Button](https://design-system.service.gov.uk/components/button/)
- 第一次用 / 没数据时告诉下一步怎么做（见 1.3「空」）。

### 1.2 默认
- 默认值安全、符合多数情况；危险选项不默认勾。[Good Defaults](https://ui-patterns.com/patterns/GoodDefaults)
- 占位字不冒充已填内容，标签放在框外。[NN/g 占位符](https://www.nngroup.com/articles/form-design-placeholders/)
- 记住用户上次手动选的（如聊天栏收起），但不替用户做选择（如新周期书房默认一本不加）。

### 1.3 状态齐全（每屏都画、都测）
| 状态 | 要求 | 参考 |
|---|---|---|
| 就绪 | 正常数据 | [系统状态可见](https://www.nngroup.com/articles/visibility-system-status/) |
| 空 | 说为什么空 + 下一步按钮；不是一行「还没有」就完 | [NN/g 空状态](https://www.nngroup.com/articles/empty-state-interface-design/) |
| 加载中 | 本地数据 < 1 秒不闪加载态；更久显示「正在读…」，不估剩余时间（G7） | [进度指示](https://www.nngroup.com/articles/progress-indicators/) |
| 部分成功 | 能显示的先显示，缺的那块单独说明（如 Anki 没开时其余照常） | [PAIR 优雅失败](https://pair.withgoogle.com/guidebook/patterns/errors-and-graceful-failure) |
| 出错 | 说发生了什么、用户能做什么，带行动按钮；同一错误不重复刷屏 | [GOV.UK 错误提示](https://design-system.service.gov.uk/components/error-message/)、[NN/g 错误文案](https://www.nngroup.com/articles/error-message-guidelines/) |
| 成功 | 看得见结果（G6），可撤销的给撤销入口 | [GOV.UK 确认页](https://design-system.service.gov.uk/patterns/confirmation-pages/) |
| **晚了 / 过期**（学根特有） | 琥珀色 + `!`，说晚几天、会顺到哪天；不催、不补救（Anki 只提醒，记忆 anki-reminder-only） | G3 |
| **长内容** | 长中文、长课名、很多行：截断规则写明（几行、省略号、点开看全） | 截图对比 |

### 1.4 输入与校验
- 何时校验写明（提交时为主；日期这类格式可失焦时校验）；错误写在字段旁，说「怎么改」。[GOV.UK 校验](https://design-system.service.gov.uk/patterns/validation/)
- 有上限的写上限（≤ 10 页、≤ 45 分钟），超了怎么处理。

### 1.5 反馈
- 点击 100ms 内有反应（按下态 / 禁用态）；长操作显示「在做哪一步」与已用时间，不估剩余（G7）。
- 有后果的写入完成后用户看得见（G6）。[HAX：说清系统做了什么](https://www.microsoft.com/en-us/haxtoolkit/guideline/make-clear-why-the-system-did-what-it-did/)
- 核心操作对照 `docs/platform/SPEED-BASELINE.md`，比基线慢要说明。

### 1.6 确认与撤销（学根的三档，选一档写进功能卡）
1. **本地小写入**（读完了、读完这段）：先等 10 秒再写，期间「撤销 · N」。
2. **改库的事务**（收课、改计划、开周期、排书）：经总控 / `course_close` / `course_plan`，先在聊天里给看改动、用户说可以才写；写完一笔 jj，可「撤销这次 …」。
3. **不可恢复**（删东西、覆盖用户手写内容）：确认对话框，写清后果，主按钮写动作名不写「确定」。[NN/g 确认对话框](https://www.nngroup.com/articles/confirmation-dialog/)、[APG 对话框](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)
- 能撤销就不弹确认。[Undo](https://ui-patterns.com/patterns/undo)
- 进行中的生成、打开的面板能快速关掉（Esc）。[HAX 高效关闭](https://www.microsoft.com/en-us/haxtoolkit/guideline/support-efficient-dismissal/)

### 1.7 键盘与读屏
- 主路径只用键盘能走完；Tab 顺序 = 视觉顺序；对话框锁焦点、Esc 关、关后焦点回到触发按钮。[APG](https://www.w3.org/WAI/ARIA/apg/)
- 标签页用 `role=tab`、菜单用 menu-button、`/` 菜单用 combobox；表格类（周表格）格子按钮有可读名称（「11-12 周四 · 主项课 · CTM D1」）。
- 状态不只靠颜色：配记号 ●!✓○◌（G3），读屏读得到记号含义。
- 焦点环 `--accent-11`、2px，深浅色都 ≥ 3:1。[WCAG 2.2 速查](https://www.w3.org/WAI/WCAG22/quickref/)
- `prefers-reduced-motion` 下没有动画也能用。
- 验证：组件测试查角色与名称；手动 Tab 走一遍记在验收表。

### 1.8 文案
- 只来自 `strings.ts`（G2）；词表第三节；`npm test` 末尾用词闸门 0 处。
- 不出现路径、脚本名、`/skill:`、内部词（G4），包括**按钮代发给模型的指令**——不显示成用户消息。
- 日期写法统一（`11-12 周四`），不估时长（G7）。

### 1.9 依赖缺失与降级
- Anki 没开、没网、OpenDesign 503、jj 不在 PATH：各有一句明确状态 + 能做的下一步，其余功能照常（部分成功）。
- 读 / 写边界写清：面板只读；写库只经事务工具；写 Anki 只经收课 / 制卡的 `anki-sync`（11-09 起直连，会写卡）。

## 2. 视觉（依据：`BEAR-VISUAL-PLAN.md`、Radix、Refactoring UI、Apple HIG）
- 只用 Bear 变量（`--gray-*`、`--accent-*`、`--warn-*`、`--done-11`、`--fs-*`/`--lh-*` 成对、`--sp-*`、`--r-*`）；散值要在任务单里说明理由。
- 文字对比度 ≥ 4.5:1（浅、深两套，所有底色层级都算，含 hover 底）；弱化文字也不能低于。
- 主次：每屏只有一个最重的东西；间距分组，不靠加框。
- 状态补齐：hover / selected / focus / disabled / loading。
- **样式真的生效**：验收时用 CDP 量关键元素的计算样式（边框、留白、字号），不只看类名在不在（11-12 教训：`.bear-pb button` 重置把格子线吃掉，测试全绿）。
- 宽度：1280、1920、≤ 900 三档；深色、浅色；打印（若有）。

## 3. 一致性与场景（依据：`CHECK-PROCESS-1111.md`）
- 同一事实只算一次：新显示处必须调用共用函数，并进 `consistency.test.ts`。
- 任务单列出「这段文字 / 这个事实还在哪些地方显示」，验收逐处核对。
- 场景走查：在 `SCENARIOS.md` 里加本功能相关的日内状态（用 `XUEGEN_TODAY` 固定日期），走查脚本读文字逐条断言 + 截图；点标签页只认 `role=tab` 且确认已激活。

## 4. AI 功能（依据：HAX、PAIR）
- 说清能做什么、不能做什么（入口按钮的悬停说明写「会改什么」）。[HAX 18 条](https://www.microsoft.com/en-us/haxtoolkit/ai-guidelines/)
- 能停：回答中 Esc / ■ 停止，停止清排队、原话回输入框。
- 能纠正：改库前给看改动，用户说可以才写；写了能撤销；风格只管本次会话（G8）。[PAIR 反馈与控制](https://pair.withgoogle.com/guidebook/patterns/feedback-and-control)
- 标来源：讲课、领域问答说依据（科目页、课程页、原书页码）；库里没有就直说没有，不编引用。
- 不把不确定说成确定：日期、进度、第几周一律以脚本输出为准，模型不自己推算；估不准的不估（G7）。[PAIR 信任校准](https://pair.withgoogle.com/guidebook/patterns/calibration-of-trust)
- 出错：断线自动重试的提示不刷屏，恢复后只留一行；失败时库不留半截（事务）。[PAIR 优雅失败](https://pair.withgoogle.com/guidebook/patterns/errors-and-graceful-failure)

## 5. 脚本契约（给 AI 和界面用；学根没有给用户的命令行）
- `--json` 输出结构写进技能文档并有测试；报错非 0 退出、中文说原因；认 `--today` / `XUEGEN_TODAY`；会写文件的命令默认只打印、`--write` 才写。[clig.dev](https://clig.dev/)

## 6. 验收方法（顺序固定）
1. 机器：typecheck、lint、单测、用词闸门、一致性测试。
2. 设计稿 vs 实物**逐元素表**（✓ / ✗ / ?），同宽并排截图（设计稿与真窗口），关键元素量计算样式。
3. 场景走查全过。
4. 按本清单逐项填结果，没验证方式的不算 ✓。
5. 设计稿没画、Claude 自己定的地方单独列给用户看。

## 7. 示例：现有功能的清单要点

### 7.1 AI 对话（Composer、活动行、停止）
入口：每个会话底部输入框。三档撤销：— （对话本身不改库）。
- 1.1/1.8：Enter 发送、Shift+Enter 换行、输入法选字回车不发送；`/` 只是快捷方式。
- 1.3：活动行只一行（思考 / 查资料 / 动手 / 写）+ 已用时间与步数，> 3 分钟标 long；断线重试提示（**现缺**：连续失败两次时第一条不撤）。
- 1.6/4：Esc 或 ■ 停止；`/` 开着时 Esc 先关菜单；停止清排队、原话回输入框（有字不覆盖、按钮代发的不放回）。
- 1.8：按钮代发的指令折叠成中文动作名（**现缺**：建课、做卡、周核实仍显示成用户消息——随总控面板批修）。
- 4：风格「默认 / 大白话 / 细讲 / 深度」只管本次会话，默认跟科目讲解偏好。
- 1.7：输入框、停止按钮、`/` 菜单的角色与名称有组件测试。

### 7.2 卡片
入口：课程会话侧栏「卡片」；总控里在面板「卡片」块（11-12 起）。
- 1.3：Anki 没开 → 「Anki 没开」+ 其余数字照常（部分成功）；空库 → 说怎么加第一张（「新卡片」或上课时「制卡」）。
- 1.9：面板只读；写卡走收课 / 制卡的 `anki-sync push`（直连 AnkiConnect，会写卡，有卡片 ID 回填）。旧的「写入库，由 Obsidian 同步到 Anki」已不对（插件 11-10 停用）。
- 1.4：「新卡片」正面不能空，提交时校验、错误写在字段旁。
- G7：「待同步」不做成估时进度条。

### 7.3 开课与收课
入口：今日卡 / 总控面板「今天」行的「开课 →」；课程会话输入区右侧「总结 · 制卡 · 收课」。
- 1.3：点开课先出本地「课程开场卡」，再读文件；已收课的课不再显示「开课」（11-11 修，一致性测试覆盖）。
- 1.6：收课 = 第 2 档（暂存 → 校验 → 一次提交 → jj），回答后换成「撤销这次收课 · 制卡」；「读完了 / 读完这段」= 第 1 档 10 秒撤销。
- 1.5：开课 / 收课是固定流程，**现缺**「开课 · 第 3/8 步 · 顺延排期」这样的步骤显示（界面讨论清单）。
- 3：收课后回看今日卡、总进度、日历是否一致（场景 S1）。

### 7.4 总控面板（11-12 设计稿 `?d=dash`，待做——用它试用本清单）
- 入口：打开学根默认落在总控；总控里没有侧栏。默认：今天 + 本周。
- 1.3：每块各自的空 / 加载 / 出错（如书房没书：「还没有在读的书」+「加一本书」；Anki 没开：卡片块与 Anki 状态格显示「没开」，其余照常）。
- 1.6：面板上的按钮只发话给总控（第 2 档）；「读完这段」第 1 档。
- 1.7：周表格格子是按钮，读屏名称含日期、行、内容；状态格是只读文字不是按钮。
- 2：1280 / 1920 / 900 三档、深浅色、打印整页。

## 修订说明（相对用户原稿改了什么、为什么）
1. **过时事实已改**：「AnkiConnect 只读」→ 11-09 起卡片直连、会写卡（面板只读）；「写入 wiki/flashcards」→ 该目录 11-10 改名后已不存在；Bear「太久了可以点停止」11-10 已删；G7 11-11 放开了预计日期；G1「只有一栏正文」对总控已不适用（11-12 改成一页面板，SKIN-LEDGER G1 待同步）。
2. **链接改成仓库内相对路径**：原稿链到 GitHub `main` 分支，`main` 比工作分支 `desktop` 旧，看到的台账不是最新。
3. **加了「分级」**：原稿每个功能要过 12 节，改一个文案也要全过，执行不下去就会被跳过；现在按 A / B / C 三级。
4. **加了「验证方式」要求**：原稿只列「要什么」，不说「怎么证明」。11-12 周表格的问题正是「✓ 了但没真验」——没有验证方式的 ✓ 不算。
5. **加了视觉一节（§2）**：原稿没有视觉数值检查，而学根这几次返工多半是视觉走样（对比度、尺度、样式没生效）。
6. **加了学根特有的三节**：一致性与场景（§3，11-11 起的查 bug 流程）、撤销三档（§1.6，原稿只说「确认或撤销」，学根实际有三种机制）、状态里加「晚了 / 过期」「长内容」。
7. **AI 一节补了三条学根踩过的坑**：按钮代发指令不显示成用户消息、改库前给看改动、日期以脚本为准不让模型推算。
8. **§1.12 CLI 改成「脚本契约」**：学根没有给用户用的命令行，脚本是给 AI 和界面调的，要求换成 `--json` 契约、`--today`、默认不写。
9. **示例加了一份「总控面板」**：下一批就用它试本清单。原稿说没有「新建科目」界面是对的——登记资料现在在总控聊天里做，批 4 的「加一本书」对话框和批 5 的开周期向导出来后再补清单。
