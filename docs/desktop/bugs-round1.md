# 第 1 轮使用测试 bug 记录（Claude 亲自按真实流程测试）

环境：`XUEGEN_HOME=/tmp/chk/t1-home`（凭据为指向用户 `~/.xuegen` 的符号链接，其他设置为副本），库副本 `/tmp/chk/t1-vault`，真实模型。每条：复现步骤 / 预期 / 实际 / 严重度（P0 阻断使用，P1 明显错误，P2 体验问题）。

## 用户已报告

### B1 宽窗口下对话正文贴左，右侧大片空白（P2）
- 复现：窗口宽 1920，对话窗口 1420px，正文与用户消息列（最宽 640px）贴左，右侧约 750px 空白。
- 预期：正文列与输入框在对话窗口内居中，宽度 640–720px 随窗口变化。

### B2 部分用户消息下面没有任何回答（P0，待复现）
- 用户窗口中「你好」「/skill:diagram 用条形图…」「开始今天的 CTM…」下都没有回答、没有「已停止」或错误提示。

### B3 关掉侧边小窗口后再也打不开（P0，用户报告）
- 复现：点「今天」或工具窗标题栏左上角的关闭框 → 窗口消失；再点右侧图标、菜单都无法重新打开。
- 预期：点图标列的图标总能打开（或切换到）对应工具窗；「今天」可从「学习」菜单与图标列重新打开（图标列加「今天」图标）；「显示」菜单加「显示全部侧窗」。关闭状态可以持久化，但必须有入口恢复。

### B4 默认模型用了慢的 Pro，且切换模型不被记住（P1，用户报告「思考太慢」）
- 现象：`~/.xuegen/settings.json` 默认 `deepseek-v4-pro` + `defaultThinkingLevel: high`，一次回答 108 秒。Claude 已把用户默认改为 `deepseek-flash`。
- 要修：在「模型」菜单选择模型后写回默认（`settings.json` 的 `defaultProvider/defaultModel`，经 agent 用 Pi 的设置接口，不手写 JSON）；「模型」菜单增加「思考强度：低/中/高」并同样记住；菜单栏右侧显示当前模型短名（如「Flash」），一眼可见。

## Claude 测试发现

### B5 模型错误：余额不足显示成「模型出错了」（P1）
- 实际：`402 {"message":"Insufficient Balance"…}` → 「模型出错了」。
- 预期：识别 402 / `insufficient_balance` →「DeepSeek 余额不足：请充值，或在「模型」菜单换一个模型」。`translateModelError` 加此类并测试。

### B6 「模型」菜单列出没有可用凭据的模型（P1）
- 实际：菜单里有十几个 Claude 模型，但没有有效 Claude 凭据（调用即 401）。
- 预期：只列出有凭据的提供方的模型；或把无凭据的分组置灰并注明「未登录」。

### B7 第一次点「继续学习」没有反应（P1）
- 复现：应用刚启动、模型列表未就绪时点「继续学习」，什么都没发生（没有消息、没有提示）；第二次点才发送。
- 预期：agent 未就绪时按钮显示「准备中…」并禁用，或把请求排队到就绪后发送。不能静默丢弃。

### B8 `/` 菜单回车执行了错误的命令（P0）
- 复现：输入 `/进度` 回车 → 执行了「/今天学到这里」（因为它的说明里含「进度」且排在前面），把收尾指令发给了模型。输入 `/技能` 回车 → 输入框变成 `/skill:article`（分组名「技能」匹配到了第一项）。
- 预期：排序优先级：命令名完全匹配 > 命令名前缀匹配 > 命令名包含 > 说明/分组匹配；回车执行排序后的第一项。补测试：`/进度`→进度，`/技能`→技能，`/日历`→日历，`/深`→深度。

### B9 没有 `/新会话`，未知斜杠命令被当作普通消息发给模型（P1）
- 复现：输入 `/新会话` 回车 → 作为「[风格：深度] /新会话」发给模型。
- 预期：加入内置命令 `/新会话`（新会话）与 `/继续会话`（继续最近会话）；任何未匹配的 `/xxx` 不发送，在菜单里提示「没有这个命令」。斜杠命令不加风格前缀。

### B10 检验题从不以「检查理解」对话框出现（P1）
- 实际：teach 出的复习题是普通编号列表，界面里的「检查理解」框与「我来回答 / 给点提示 / 跳过」从未出现。
- 预期：`skills/teach/SKILL.md` 规定检验题用 `> [!question] 检查理解` callout 输出（每题一个或一组）；三个按钮的行为：我来回答 → 聚焦输入框并在输入框上方显示「正在回答：第 N 题」；给点提示 → 发送「给我第 N 题的提示」；跳过 → 发送「跳过第 N 题」。

### B11 「下次接着读」没有记录读到哪（P1）
- 实际：点「下次接着读」直接排到后天，`position` 仍为空，面板一直显示「未开始」。
- 预期：点击后弹出小输入「读到哪了？（页码或小节）」，可留空；写入 `--position`。

### B12 新加入的阅读要明天才能读（P2）
- 预期：「加入阅读」旁加「今天就读」勾选（默认勾选），勾选时到期日为今天。

### B13 日历详情不清楚（P2）
- 学习记录只显示「2026-10-21-01（课程创建，非收课）」没有课程名，两门课同日会出现两条一模一样的；日志行是原始的「log course | …」。
- 预期：每条记录前显示课程名；日志去掉 `log` 前缀，按「类型 · 内容」显示；格子里的 ● ◆ ▲ 太小看不清，放大到与日期数字同高。

### B14 「课程活动」含义不明（P2）
- 「今天」窗口的「课程活动」数字从 0 变 1，看不出指什么。改为「今天计划」并在悬停/点击时列出具体项（来自日历当天的计划与记录）。

### B15 `/加入阅读`、`/制卡` 只打开面板（P2）
- `/加入阅读` 打开阅读窗后应聚焦「加入阅读」输入框；`/制卡` 应按说明「把这次学到的内容起草成卡片」发送给学根，而不是只打开卡片窗。
