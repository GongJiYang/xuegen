# F5：回答被意外「停止」（用户真实使用发现）

现象：用户发 `/skill:diagram 用条形图比较我 6 门课的总进度`，学根读了 6 个文件、正在写答案时被中止，界面显示「模型出错了」，详情 `Request was aborted`。会话记录里最后一条 assistant `stopReason: "aborted"`。唯一会发 `abort` 的地方是输入框按钮：生成中「发送」原地变成「停止」，用户再点一下（想追问或双击发送）就把回答停掉了。

## 要改的

1. **生成中输入框有内容时，按钮是「发送」**（作为追问排队，协议已支持 `streamingBehavior: "followUp"`）；只有输入框为空时才显示「停止」。回车同理：有内容就排队发送，绝不触发停止。
2. **防双击**：点「发送」后 600ms 内的第二次点击忽略。
3. **停止要明确**：「停止」按钮用与发送不同的样式（Chicago：普通按钮，非默认按钮粗外圈）；生成中在输入框上方的风格行右侧显示「生成中… Esc 停止」，Esc（输入框为空且没有 `/` 菜单时）也能停止。
4. **被停止不是「出错」**：`translateModelError` 把 `aborted` / `Request was aborted` 显示为「已停止。可以继续提问，或点「重试」」，不弹警告框、不闪菜单栏；消息下方加「重试」按钮（重发上一条用户消息）。真正的错误仍按原规则。
5. 测试：按钮状态（空/有内容 × 生成中/空闲）、防双击、Esc、aborted 文案与不弹窗、重试。
