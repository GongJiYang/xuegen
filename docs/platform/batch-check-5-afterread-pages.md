# batch-check-5-afterread-pages（DeepSeek，约 15 分钟，先写测试）：讲后读页码从没记进书页

现象（Claude 11-12 场景走查 S4）：测试窗口点讲后读「读完了」，课程页打勾、书页读书记录多一行，但书页**没有** `## 讲后读已读` 一节。
根因（Claude 已查清）：`skills/course/course-state.mjs` 约 154 行只认 `核心页已定：pp.…` 这种写法取页码；而技能规定的写法是「讲后读 §x–y pp.a–b · YYYY-MM-DD 读」，真实课程页里的行是：
- `- [ ] 讲后读 §1.1–1.4 核心页 · 2026-11-10 读（pp.1–5、7–12、17–21、24–27、31；完成条件：读完，并能说出一个要点或疑问）——今天开课时问到，用户答「没读」，仍待读`
- `- [ ] 讲后读 §2.3 核心页 · 2026-11-12 读（核心页今天已定：pp.66–75——有效性与真值表检验法…）`
- `- [ ] 讲后读 §2.1–2.2 核心页 · 2026-11-12 读（pp.40、43–46、54、56–59；11-10 排着 D1 的讲后读，故顺到 11-12；…）`
三种都取不到页码 → `pages: null` → 主进程不带 `--pages` 调 `bookshelf lecture` → 不记「讲后读已读」。11-08 起一直如此（单元测试用的是脚本自己约定的格式，所以一直绿）。

约束：只改 `skills/course/course-state.mjs` 与它的测试；不 commit / push；**自己做完，不要调用 `pi`、`devin` 或别的 agent**。

## 改法
1. 先写测试：上面三行原文（照抄）各一条，期望 `pages` 分别为 `1–5、7–12、17–21、24–27、31`、`66–75`、`40、43–46、54、56–59`；再加技能规定格式 `- [ ] 讲后读 §2.4 pp.56–63 · 2026-11-13 读` → `56–63`；旧格式 `核心页已定：pp.12–15` → `12–15`；没有任何 `pp.` → null。看它们失败。
2. 实现：取这一行里**第一个** `pp.` 后面的页码列表（数字、`–`、`-`、`、`、`,`、`，`、空格组成），去掉尾部分隔符；`核心页已定：pp.` 的写法自然也被覆盖。页码列表后面紧跟中文说明（如 `——有效性…`、`；完成条件`）时要截断在列表结尾。
3. 输出格式、其余字段不变。函数头注释更新。
