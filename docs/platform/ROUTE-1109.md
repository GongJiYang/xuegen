## 阶段 3　收课事务（解决今天那种「写了一半、没上锁」）　✅（v0.8.0，11-10 真机验收通过；**11-11 全量测试发现：装好的学根从访达启动找不到 jj，jj 提交与撤销在真实使用里从没成功过——fix15 已修，待发版**；设计 `STAGE3-DESIGN.md`；第 3 项「已收课只读」随界面讨论）（原 A2、2）；用户 11-09 定：模型把要改的文件写进本次收课的暂存目录，`course-close.mjs` 校验、查冲突、一次替换、上锁、jj 提交；Anki 加卡在提交后照常同步，不进事务；「已收课只读」等界面讨论
1. **新脚本 `course-close.mjs`**，提供 `stage / commit / abort / undo`：
   - **暂存**：用 `copyFile` 加 `COPYFILE_FICLONE`，在同一个卷上做写时复制；跨卷时退回普通复制。
   - **封存**：记下这次读过哪些文件、各自是哪个版本，要写哪些文件。
   - **冲突检查**：封存时查一次，提交前再查一次。
   - **提交**：先写提交日志，再对每个文件做「写临时文件 → fsync → 关闭 → rename」，然后上锁，最后删掉日志。启动时如果发现残留的日志，就补完或回退。
   - **效果分三类，写死在脚本里**：可缓冲的（库里的页面）先暂存；可逆的（Anki 加卡）提交后才做，撤销时反向操作；不可逆的放到最后，尽量不引入。
2. **`course` 技能改流程**：收课时产出一个「收课包」，再调用 `commit`；模型不再直接改课程页。课程页的锁也只有这个脚本能解开。
3. **会话标成「已收课」，界面变只读**，对应骨架 3.10。
4. **讨论稿里写明保证到哪一级**：单个文件是原子的；整次收课靠提交日志保证崩溃后一致；断电后不丢数据取决于 `F_FULLFSYNC`（Node 在 macOS 上用的 libuv 应该会走它，要实测确认）。
