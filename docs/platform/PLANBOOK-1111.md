## 用户定的规则
1. **只有两种排期**，区别只在有没有完结：
   - **周期排期（有完结）**：主项课。7 周学时，日期跟实际走（11-10 已定，不改）。每个主项 7 周只主攻一份主资料。
   - **书房排期（不设完结）**：其余所有书，按读法往后排，没读就整体往后挪，不截断、不再有「留到下个周期」。
2. **书房三种读法**：讲后读（跟主项课：课上定核心页，隔天读）、带读（学根陪读：概览、术语、地图，每次 ≤ 45 分钟，不考核——原来的「辅助课」）、自读（自己读原文，读完记一笔，每天一段 ≤ 10 页）。带读按选定的星期几，同一天只排一本带读。
3. **目标日期可选**，只用来和预计日期对比（「照现在的进度会晚 15 天」），不为赶日期加量。
4. **辅助资料排不排由用户定**：登记 ≠ 排期；新周期默认什么都不加。
5. **开下一周期**：总控做（技能），入口是周计划本最后一周的按钮；向导 5 步：验收上一周期（未达标：恢复周 / 先开下一周期、剩下转书房自读）→ 选主项（最多两个，路线建议预勾、可换）→ 每个主项选一份主资料（原来带读的书：接着进度讲 / 从头精讲）→ 书房要不要加（默认不加；带读的书变主项后带读自动停）→ 一周预览 → 交给总控写入（一次提交，可撤销）。
6. **总控 = 周计划本为主、聊天为辅**：日 / 周 / 月视图、本周目标（周核实）/ 本周复盘（整合日）、打印；行 = 主项课 / 讲后读 / 带读 / 自读 / Anki。
7. **Anki** 只一行提醒 + 今日张数，没刷不标、不提醒。
8. **日视图时间格**：一格 10 分钟，只记实际（上课、带读按会话起止；自读按「读完这段」前的打开时间），可点一下改起止；不预估。
9. 改动都经总控：界面按钮只发话给总控，总控在聊天里给看改动，用户说可以才写库（计划事务，可撤销）。

## 拆批（顺序）
1. **逻辑批（不动界面）**：
   - 辅助课去完结：技能里辅助加 `end`、「留到下个周期」的段落删掉；真实库 c-language、algorithms-sedgewick 去 `end=`、把挪走的课次放回（改库前给用户看、先备份）。
   - 带读：辅助课在数据上仍是课程页（课次内容在那里），对外改叫「带读」，归书房这一栏；`cycle.mjs day` 等输出保持兼容。
   - 书房目标日期：书页 frontmatter 加可选 `target:`，`bookshelf.mjs` 输出 `target`、`targetLate`。
   - 新周期流程：cycle-plan 技能「新建周期 / 轮换」改成上面 5 步，去掉「上一周期辅助自动转主项」。
2. **数据接口批**：给周计划本一个汇总接口（一周 / 一天 / 一月：主项课次、讲后读、带读、自读、Anki 数、周核实、整合日复盘），纯函数 + 测试。
3. **界面批 A**：总控周计划本（周 / 日 / 月、打印），聊天收到右侧；窄窗（≤ 900）聊天默认收起。
4. **界面批 B**：总进度（两种排期分开）、书房（读法标签、目标、已登记未排）、加书对话框。
5. **界面批 C**：开下一周期向导 + 最后一周横幅。
6. **时间记录批**：会话起止与「读完这段」时间落盘，日视图时间格读它；可手改。
