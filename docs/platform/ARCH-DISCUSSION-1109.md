## 2. 文件夹要不要收敛：要，但「数据」和「代码」分开收

**建议：一个「学根数据根」，代码仓库保持独立。**

```
~/学根/                       ← 唯一需要备份、迁移的东西（Finder 里一眼能找到）
├── 库/                       ← 现在的 GJY：wiki/ raw/ Clippings/ AGENTS.md（Obsidian 打开这一层）
│   └── raw/books/            ← 学习路径里的教材搬进来（准则第 2 条）
├── 会话/                     ← 现在的 ~/.xuegen/sessions
├── 工作区/                   ← 现在的 ~/learning（agent 的 cwd，实验代码）
└── 设置/                     ← settings.json、wiki.json 等（不含凭证）
凭证（auth.json、mcp-auth.json）→ macOS 钥匙串或留在 ~/.xuegen，不进数据根、不进版本库
可重装的（mcp-tools、bin）→ 留在 ~/.xuegen，不备份
```

**为什么不把 wiki 并进 xuegen 项目文件夹**：
1. xuegen 仓库是**公开**的 GitHub 仓库；库里是你的学习记录、答题、会话，并进去就公开了（或者整个仓库被迫变私有）。
2. 两者节奏不同：代码按版本发布、可以回滚；库每天都在变，回滚代码不应该连带回滚学习记录。
3. 学根要能给别人用：同一份程序，不同人的数据根不同。

「融入」想要的好处——一个地方、好迁移、能一起管——用「一个数据根 + 一个设置项指向它」就能拿到。

**要用户定**：数据根放哪（`~/学根/`？放 iCloud 里？）；教材 543 MB 要不要一起搬进 `raw/books/`。

## 4. 库必须是 Obsidian 吗：不必须，但现在有两处硬依赖

学根读写的都是普通 Markdown 文件，Obsidian 只是**一个**查看和编辑工具。要摆脱依赖，只需改两处：
1. **卡片同步改由学根直接做**：学根已经连着 AnkiConnect（卡片面板在用），可以直接把卡写进 Anki 并记下卡片 id，不再经过 Obsidian_to_Anki 插件。这样「做卡」从「写文件 → 你去 Obsidian 点同步」变成一步完成，也方便书房做卡直接进「书房::Epp」牌组并设预设。
2. **链接写全路径**（`[[知识/concepts/math/…]]` 或相对路径），不靠后缀解析。

**建议**：格式继续兼容 Obsidian（你习惯用它看库，图谱、反链都好用），但学根的任何功能都不再**依赖** Obsidian 打开着或装了某个插件。

**要用户定**：卡片同步要不要改成学根直连 AnkiConnect。

## 5. 用 jj（Jujutsu）管库

jj 是兼容 Git 的版本管理工具（底层仍是 git 仓库，可以推到 GitHub 私有仓库）。和直接用 git 比，它有几样正好对上学根的需要：

| jj 的特性 | 对学根意味着什么 |
|---|---|
| **工作区自动快照**：每次运行 jj 命令时，工作区的改动自动记成一个提交，不用 `git add` | 学根和你在 Obsidian 里的改动都会被记下，不会「忘了提交」 |
| **操作日志 + `jj undo`**：每个 jj 操作都可以撤销，包括撤销一次合并或回退 | 「撤销这次收课」可以真正回到收课前，而不是靠模型手工改回去 |
| **冲突是一等公民**：冲突记在提交里，不会卡住后续操作 | 多个会话同时改库时，冲突先记下，事后再处理，不会把流程卡死 |
| **多工作区**（`jj workspace add`）：同一个仓库开多个工作目录 | 每个会话进程可以在自己的工作区里改，提交时再合并——这就是论文里「写时复制工作区、提交或丢弃」的现成实现 |
| 与 git 共存（colocated） | 推到私有 GitHub 仓库做备份和换电脑 |

**代价与风险**：
- jj 还是 0.x 版本，要把 jj 程序打包进学根，或者让你安装（本机现在没有）。
- 快照发生在「运行 jj 命令时」，不是实时的：你在 Obsidian 里写了一半、没触发 jj 命令就关机，那部分不在历史里（文件本身还在）。
- 多工作区意味着同一个页面在不同工作区可能有不同版本；Obsidian 只打开主工作区，看到的是合并后的结果。
- 教材这类大 PDF 不宜进版本库（543 MB），`raw/books/` 要排除，另做备份。

**建议**：库用 jj（与 git 共存）+ 私有远端。先只用「自动快照 + 操作日志 + 推送备份」，多工作区等第 7 节的多进程定了再用。

**要用户定**：用 jj 还是先用纯 git；私有远端放 GitHub 私有仓库还是别处。

## 7. A1 会话进程（细化）

### 7.1 角色与权限清单（每类会话一张，写死在代码里，学根自己改不了）

| 角色 | 读 | 写（只能经过列出的方式） | bash | 网络 |
|---|---|---|---|---|
| 总控 | 整个库 | 只经脚本：`cycle.mjs`、`course-state.mjs` 的改计划命令；`log.md` 追加 | 只读命令（ls、grep、cat、pdftotext 等白名单） | 模型 API |
| 课程（每门一个） | 整个库 | 自己的概念目录（`知识/concepts/<科>/`）、`知识/flashcards/<科>/`；**课程页只能经收课包脚本写**（第 8 节） | 白名单 + 自己的实验目录 | 模型 API |
| 书房（每本一个） | 这本书、它的 source 页、相关概念页 | 只经 `bookshelf.mjs`（摘录、记录） | 只读命令 + `pdftotext` 读这本书 | 模型 API |
| 领域记忆（RAG，每领域一个） | 这个领域的 wiki、原书、摘录、过往会话（只读） | **什么都不写** | 只读命令 | 模型 API |
| 自由提问 | 整个库 | 不写库；只写工作区 | 工作区内任意 | 模型 API + 联网工具 |

规则写成「工具名 + 参数」的形式（例：`edit` 的 `path` 必须在某目录下；`bash` 的命令必须匹配白名单），每次调用前确定性检查。会话进行中**只能收紧、不能放宽**：要放宽（比如自由提问里想改库），就弹框问你，你批准一次只放这一次。

### 7.2 执行在哪里检查（三层，由便宜到贵）

1. **工具层**（必做）：在 agent 进程里包住 read / write / edit / bash，按角色清单检查路径与命令；被拒时返回明确的错误给模型（「书房会话不能写课程页」），同时记一行审计。
2. **文件系统层**（必做）：每个会话进程只拿到它需要的目录——用 jj 多工作区或写时复制目录，让「写」先落在会话自己的副本上，提交时才合回库（与第 8 节的事务是同一套机制）。
3. **系统层**（后手）：bash 套 macOS 沙盒。`sandbox-exec` 能用，但苹果在手册里标了 DEPRECATED（本机 man 页已核对）；更正统的做法是用苹果的虚拟化框架跑一个很小的 Linux 虚拟机（SideKernel 的路线，见第 6 节，成熟度还不够），凭证留在宿主机。只在要跑不受信任的代码（实验、下载的脚本）时启用，平时不开，避免变慢。

### 7.3 进程与主管（Erlang 式）

- 主进程当**主管**：打开一个会话就起一个 agent 进程（Electron `utilityProcess`，约 100 MB），带上角色与清单；同时最多 4 个，超过就让最久没动的那个休眠（退出进程，会话文件还在，下次打开从文件恢复）。
- **会话之间不发消息、不读对方对话**，只通过库交换结果；库里每个文件有且只有一个「主人」（课程页 → 收课脚本；书页 → bookshelf.mjs；概念目录 → 该科课程会话）。这把准则第 3 条「一件事只在一个地方」变成硬规定。
- **出错的处理**：一次回答断线 → Pi 自己重试；进程崩溃 → 主管重启它，从会话文件接着；收课中途失败 → 事务回滚（第 8 节），界面告诉你「这次收课没生效，可以再收一次」。
- **界面**：顶部标签页列出开着的会话（总控 · 离散 · 书房 Epp · 领域：离散数学），后台会话在跑时标签上有动静；收完课的会话标签变灰、只读。
- 跨进程消息都带 `sessionId`（这一步现在就该做，便宜）。

### 7.4 分步

1. 协议加 `sessionId`；工具层权限清单（单进程也能用）。
2. 收课事务（第 8 节）。
3. 多进程 + 主管 + 标签页 + 休眠。
4. 领域记忆会话（RAG）挂上来。
5. 系统层沙盒（需要时）。

## 8. A2 收课事务（细化）

### 8.1 先分清收课会产生哪几类「效果」

| 类别 | 收课里的例子 | 怎么处理 |
|---|---|---|
| 可缓冲（Atomix 的 bufferable） | 课程页打勾与 Learning Record、概念页、`index.md`、`log.md`、快照图片 | 先写进暂存区，提交时一次替换 |
| 可逆（reversible，可补偿） | 往 Anki 加卡（可以删掉）、改 Anki 牌组预设 | 提交后再做；失败或撤销收课时执行反操作（删卡） |
| 不可逆（irreversible-gated） | 发通知、外部服务上传（现在没有） | 只能在提交成功后放出；失败就不放。Atomix 指出：有 2 个以上不可逆效果时仍可能只提交一半，所以学根尽量不引入不可逆效果 |

每个效果归哪一类**写死在 `course-close.mjs` 里**，不让模型标（Atomix 实测：类别标错会漏出 17/200）。

### 8.2 流程（状态机）

```
收课开始 ──► 准备：模型读材料、和你核对，产出「收课包」（不碰正式文件）
              │   收课包 = 打哪些勾、记录正文、概念页的新增/修改（完整文本）、下次起点、要加的卡
              ▼
           封存：脚本记下这笔事务要读哪些文件（及其当前版本）、要写哪些文件
              ▼
           校验：格式对不对、要写的文件是不是只属于这门课、读过的文件在这期间有没有被别人改过（有就是冲突）
              │ 冲突或校验失败 → 丢弃暂存，告诉你原因，正式文件一个都没动
              ▼
           提交：把暂存的文件一起替换进库 → 上锁 → （库用 jj 时）记一个提交「收课 D2」
              ▼
           提交后效果：加 Anki 卡、改预设（失败只影响这一步，可重试，不影响已提交的记录）
              ▼
           会话标为「已收课」→ 界面只读
```

- **撤销收课** = 对这次提交做反操作：jj 下是 `jj undo`/回退那个提交，再删掉这次加的卡。
- **中途断线**：准备阶段断了就从会话接着准备（没碰正式文件）；提交阶段由脚本一口气完成，不经过模型，断线不影响。
- 课程页只读锁从此**只由收课脚本解开**；模型的 edit 工具对课程页永远被拒（7.1）。

### 8.3 要改什么

- 新脚本 `skills/course/course-close.mjs`：`stage`（接收收课包）、`commit`、`abort`、`undo`。
- `course` 技能的收课流程改成「产出收课包 → 调 commit」，不再自己逐个改文件。
- 主进程：收到 commit 成功 → 把会话标为已收课。

## 9. 总控的改动（放进后续待做）

总控在新架构里是**一个普通会话进程 + 主管的「脸」**：
- 今日卡照旧（本地数据，不调模型）。

## 10. 落地细节（11-09 第三轮，用户补充的参考；已核对的标 ✓）

### 10.1 系统沙盒：用现成的，不从零写
- **直接包一层 `@anthropic-ai/sandbox-runtime`** ✓（Claude Code 用的就是它；Apache-2.0；npm 0.0.81，11-06 仍在更新；Mac 上底层是 `sandbox-exec`）。学根只负责按角色生成配置。
- **issue #8** ✓（已关闭）：只写 `(deny file-read*)` 挡不住 `mv`，文件可以先挪到能读的地方再读。学根自己仍要给受保护路径**以及它的每一层上级目录**都加 `(deny file-write-unlink)`，并写一条回归测试：在沙盒里 `mv` 受保护文件必须失败。
- **规则照 Codex 的基线**（`seatbelt_base_policy.sbpl` ✓ 与组装代码）来写：
  - 默认全部拒绝；
  - 可写目录本身不能删除、不能改名；
  - 只读子目录的上级目录也要保护；
  - `/tmp` 这类别名先换成 `/private/tmp`；
  - 按绝对路径 `/usr/bin/sandbox-exec` 调用，防止有人在 PATH 里放假程序。
- **Gemini CLI 的宽松档**只拿来参考参数化的写法；学根要比它严。

### 10.2 工具层路径检查：不能只比前缀字符串
APFS 默认不区分大小写，`Proj` 和 `proj` 是同一个目录；`Café` 的两种 Unicode 写法也是同一个文件（hypaware #483）。比对顺序固定为：
1. 用 `realpath` 解析。文件还不存在时，解析最深一层已存在的上级目录，再拼回剩下的部分。
2. 转成 NFC 写法。
3. 检测这个卷是否区分大小写，不区分才统一转小写。
4. 最后按路径分段做前缀比较，避免 `/a/bc` 被当成 `/a/b` 的子路径。

另外，**检查和写入要用同一次解析的结果**，不能检查完再重新解析一遍。否则在「先检查、再使用」之间，有人把路径换成符号链接，就绕过去了（论文 Mind the Gap ✓）。目前没有现成的库可用，自己写一个纯函数，配上大小写、Unicode、符号链接、不存在的文件这几类测试。

### 10.3 收课提交：用系统现成的接口
- **暂存副本**：`clonefile`，同一个卷内写时复制，几乎不花成本。Node 里用 `fs.copyFile(src, dst, COPYFILE_FICLONE)` 就会走这条路。注意三点：目标文件不能已存在；跨卷会报 `EXDEV`，这时退回普通复制；不要用它克隆整个目录，目录要逐个文件处理。
- **单个文件的原子替换**：写临时文件 → `fsync` → 关闭并检查错误 → `rename`。要做到断电也安全，`fsync` 必须走 `F_FULLFSYNC`。Node 的 `fsync` 在 macOS 上走没走它，**要实测确认**；没走的话就补一个原生调用。
- **多个文件一起提交**：`rename` 只保证单个文件。所以提交前先写一份「提交日志」，记下要替换哪些文件、各自新旧版本的位置，然后逐个 `rename`，最后删掉日志。学根启动时如果发现有残留的日志，就补完或者回退。`renamex_np(RENAME_SWAP)` 可以原子交换两个路径，在支持它的文件系统上可以用来做两个文件的互换。
- **讨论稿里要写明保证到哪一级**：
  - 默认：单个文件原子；整次收课靠提交日志保证崩溃后一致。
  - 断电后不丢数据：取决于 `F_FULLFSYNC` 有没有生效。学习笔记做到「单文件原子 + 提交日志」就够了，`F_FULLFSYNC` 能用就加上。
- **冲突检查做两次**：封存时做一次，真正提交前再做一次（Mind the Gap）。两次之间如果读过的文件版本变了，就放弃这次提交。

### 10.4 jj 多工作区
- 一个工作区改了共享的祖先提交，别的工作区就会变成「过期」状态，要用 `jj workspace update-stale` 处理（官方文档）。**所以收课提交前，先检查当前工作区是否过期**，不能默认磁盘上已经是最新的。
- 工作区只能隔离编辑工具：shell 里用 `cp` 或重定向写到工作区外面，是拦不住的（Claude Code 的 worktree 文档也这样写）。**所以工具层检查和系统沙盒两样都不能省。**

### 10.5 支持「权限清单写死」的实验结论
- **AuthBench**（2605.14859 ✓）：让模型自己生成文件级权限，会同时出现给少了和给多了的情况，多推理几轮也不会自己收敛到最小权限。**所以清单写死在代码里，不交给模型生成。**（它的仓库目前几乎是空的。）
- **Atomix 的类别名**按原文更正：可缓冲（bufferable）、可逆（reversible，含 reversible-with-cost）、不可逆需等提交（irreversible-gated）。第 8.1 节已经按这个写。
