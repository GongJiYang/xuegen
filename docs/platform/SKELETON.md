# 学根功能骨架（第一性原理）

2026-11-09 用户要求：从「学根到底为了什么」往下拆，一直拆到**不能再细分的叶子**——一个叶子 = 用户的一个动作 + 一个看得见的结果。每片叶子写清楚：靠什么做（技能 / 脚本）、写在哪（库里的一个地方）、在界面哪里（入口）。这份是全项目的目录：新功能先找到它挂在哪根树枝上，挂不上就说明需求还没想清楚；用户手册、皮肤台账、任务单都从这里引用。

状态：✓ 有 · ◐ 部分 · ✗ 还没有 · 💡 用户提过、未定

## 根

**学根 = 让我在两年路线里，按计划学懂、读完、记住，并且随时能找回学过的东西。**

拆分依据——学一样东西，只有这几件事必须发生，缺一不可、互不重叠：

```
学根
├── 1 定方向   要学什么、为什么、按什么顺序
├── 2 排今天   今天具体做哪几件
├── 3 学懂     有人讲、我练、被检验
├── 4 读原文   整本书按页读完
├── 5 记住     把要记的做成卡，按遗忘规律复习
├── 6 留记录   做到哪、证据是什么，写进库
├── 7 找回     过去学过的随时能翻、能问
└── 8 工具本身 界面、模型、更新——只为前 7 件服务
```

下面每一节是一根树枝，表格每行是一片叶子。

## 界面怎么用弹框（用户 2026-11-09）

弹框只给**必须当场做决定、而且选项有限**的时刻，其余用行内按钮：
- 用：没收课就离开后再打开（收课 / 接着学 / 不记录结束）；收课方式（正常 / 不写概念页 / 不记录）；删除、覆盖这类改动大且难撤销的操作。
- 不用：普通「下一步」、能 10 秒撤销的动作（读完了、读完这段）、只是展示信息。

## 怎么用这份骨架

1. 新需求先挂到某片叶子上（或新开一片，写清动作 → 结果）。
2. 用户手册按根下 1–7 的顺序写「一天怎么用」，按叶子编号列「每个按钮做什么」。
3. 每批收尾时更新状态列（和皮肤台账一起）。
